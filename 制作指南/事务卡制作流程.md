## 一、事务卡从注册到结算的完整链路

```
卡牌 C# 脚本 Register()
      │  CardEffectFactory.Register("JC005_lijieshu", Build)
      ▼
JCEffects.RegisterAll()  ──►  AllEffects.RegisterAll()
      │  （GameInitializer.cs:60 运行时调用；测试里用 AllEffects.RegisterAll()）
      ▼
卡片加载时：CardEffectFactory.EnsureEffects(uid) 查找构建器 → Build(PlayerCardData)
      │  向 data.EffectDataList 挂入 EffectData（含 Target / Actions / PlayTiming / Timing）
      ▼
玩家拖出事务卡（CardDragController.DragEnd）
      │  isSorceryCard && requiresTarget → Arena.BeginSorceryTargetSelection（弹窗选目标）
      ▼
确认目标 → TurnManager.PlayCard
      │  CanPlayAsResponse() 判定 C 档（任意阶段可打出，无行动阶段门禁）
      │  IsLegalPlayTarget() 取目标裁决（实时判【心】）
      ▼
效果结算 → EffectEngine 执行 Actions（消灭）；结算阶段不复检【心】
```

要点：**单卡只需在 C# 脚本里 `EffectDataList.Add` 配置效果，其余（取目标高亮、合法性、门禁、弹窗、原子锁）全部由框架按数据自动处理。**

## 二、效果数据的落地方式（真实约定）

`Script/Data/Effects/EffectData.cs:276-278` 注释规定：
> 本项目的所有具体效果均由卡片 C# 脚本在构造函数中构建并挂入 `EffectDataList`，**不序列化进 `.tres`**（`.tres` 仅保存牌面基础信息）。

实际落地采用 **静态注册表** 模式（已被 JC001/JC002/JC003/JC005/JC012/JC014/JC015/JC018/JC020/JC030/JC035/JC060/JC068 等全部采用）：

1. **每张卡一个 `…_Effects` 静态类**，内含 `Register()` 与 `Build(PlayerCardData data)`。
   - 例：`JC005_liejieshu.cs` 的 `JC005_liejieshu_Effects`
   - `Register()` → `CardEffectFactory.Register("JC005_lijieshu", Build)`
2. **系列汇总**：`JCEffects.RegisterAll()` 集中调用本系列所有卡的 `Register()`（`JCEffects.cs:15` 含 `JC005_liejieshu_Effects.Register();`）。
3. **全量汇总**：`AllEffects.RegisterAll()` 调用各系列 `RegisterAll()`（`AllEffects.cs:14-15`）。
4. **运行时注册**：`GameInitializer.cs:60` 在卡加载前调用 `AllEffects.RegisterAll()`，保证 `CardEffectFactory.EnsureEffects` 能按 UID 查到构建器。
5. **测试注册**：`JC005Tests.cs` 等测试在 `SetUp`/`_Ready` 中调用 `Cards.Effects.AllEffects.RegisterAll()`。

`CardEffectFactory.Register` 为幂等（`_builders[uid] = b`，重复调用以最新覆盖，无副作用）。

### `EffectData` 真实字段（用于 `EffectDataList` 配置）
| 字段 | 类型 | 说明（来自源码注释） |
|------|------|------|
| `EffectId` | `string` | 效果唯一标识 |
| `Timing` | `EffectTiming` | 触发时机。事务卡打出即结算用 `EffectTiming.OnSorceryCast` |
| `PlayTiming` | `PlayTiming` | 仅事务卡用，快速行动填 `PlayTiming.Response`；拖拽事务卡入堆叠阶段填 `OnPlay` |
| `Cost` | `int` | 费用数字（快速行动 N 中的 N） |
| `Forced` | `bool` | 是否强制结算 |
| `Target` | `TargetSpec` | 目标规则（见下） |
| `Actions` | `Array<EffectAction>` | 结算动作，如 `new EffectAction { Verb = ActionVerb.Destroy }` |
| `Duration` | `string` | 持续时间描述，瞬时填 `"瞬时"` |

### `TargetSpec` 真实字段（用于 `EffectData.Target`）
| 字段 | 类型 | 说明 |
|------|------|------|
| `Kind` | `TargetKind` | 目标大类，如 `TargetKind.Attachment` / `Character` / `Council` / `Region` |
| `NeedsSelection` | `bool` | 是否需要玩家在弹窗中选目标（`true` 才会走 `BeginSorceryTargetSelection`） |
| `Restrictions` | `Array<TargetRestriction>` | 条件式限制集合（取目标与复检都评估，除非被 `ExcludePlayTimeOnlyRestrictions` 剔除） |
| `Param` | `string` | 附加参数（部分限制用，如数量 / 关键字） |
| `IsLocalZone` / `IncludeCovert` / `CanTargetSelf` / `ForOpponent` / `PlayerFilter` | 各 `bool` | 区域 / 隐蔽 / 自身 / 对手 / 阵营过滤开关 |

## 三、JC005 裂解术实例详解

### 1. 文件与注册
- 实现：`Cards/Effects/PlayerCards/JC/JC005_liejieshu.cs`
- 类：`JC005_liejieshu_Effects`（静态），`Register()` → `CardEffectFactory.Register("JC005_lijieshu", Build)`
- 已被 `JCEffects.cs:15` 纳入系列注册，随 `AllEffects.RegisterAll()` 在 `GameInitializer.cs:60` 运行时生效。

### 2. Build 配置（真实代码 JC005_liejieshu.cs:25-47）
```csharp
private static void Build(PlayerCardData data)
{
    data.EffectDataList.Add(new EffectData
    {
        EffectId = "JC005_1_DestroyAttachment",
        Timing = EffectTiming.OnSorceryCast,        // 打出即结算
        PlayTiming = PlayTiming.Response,           // 快速行动：有优先权即可打出（含响应窗口/堆叠非空）
        Target = new TargetSpec
        {
            Kind = TargetKind.Attachment,
            NeedsSelection = true,
            Restrictions = new Godot.Collections.Array<TargetRestriction>
            {
                TargetRestriction.AttachedToCharacterIfNoMind
            },
        },
        Actions = new Array<EffectAction>
        {
            new EffectAction { Verb = ActionVerb.Destroy }
        },
        Duration = "瞬时",
    });
}
```
**设计核心**：两个分支（有【心】消灭任意附属 / 无【心】仅消灭结附角色附属）最终动作都是“消灭目标附属”，差异只在【取目标阶段】的候选范围。因此**不拆两个效果**，而是用一条条件式限制 `AttachedToCharacterIfNoMind`。

### 3. 条件式限制 `AttachedToCharacterIfNoMind`（单一真相源）
- 枚举定义：`Script/Data/Effects/TargetRule.cs`
- 实现：`TargetValidity.cs` 的 `CheckRestrictions` 分支（取目标阶段实时评估）：
  - **资产区有【心】**（`HasMindDomain`，读 `PlayerManager.GetDomainLoyalty(controller)[MagicDomain.Mind] >= 1`）→ 放行任意附属；
  - **资产区无【心】** → 目标必须“结附于角色”：`target.AttachedTo != null && AttachedTo.PlayerTemplate != null && (CategoryFlag & Character) != 0`；
    - 秘社宿主（`PlayerTemplate` 为 `null`，用 `CouncilCardData`）与结附地区的附属（`AttachedTo` 为 `null`）在无【心】时均被拦截。
- **结算复检阶段**：`TargetValidity.Check` 内部 `ExcludePlayTimeOnlyRestrictions` 剔除该限制，即结算不再复判【心】——目标未丢失即消灭（用户规则：结算时【心】是否仍在不影响）。

### 4. 取目标裁决链路（数据驱动，单卡零逻辑）
- 拖出 JC005（事务卡 + `NeedsSelection=true`）→ `CardDragController.DragEnd` 路由到 `Arena.BeginSorceryTargetSelection`。
- `CardManager.IsLegalPlayTarget(source, target)`（`CardManager.cs`）：聚合 `EffectTiming.OnSorceryCast` 的 `Target` → `MatchesSpec` → `TargetValidity.CheckRestrictions`（含上述限制）裁决候选高亮 / 合法性。
- 因此 JC005 的“有【心】全高亮 / 无【心】仅角色附属高亮”完全由 `EffectData.Target` + `AttachedToCharacterIfNoMind` 驱动，无需在卡脚本里写任何判定代码。

## 四、框架已就绪、新增事务卡无需改动的能力

以下能力在 JC005 之前已实现，新增事务卡只要把效果配进 `EffectDataList` 即自动获得，**不要重复实现**：

1. **三档打出门禁**：`TurnManager.PlayCard` 按 `CardManager.CanPlayAsResponse(card)`（遍历 `EffectDataList` 找 `PlayTiming.Response`）判定 C 档（快速行动）——任意阶段、任意优先权可打出，不收行动阶段门禁。
2. **取目标裁决单一真相源**：`CardManager.IsLegalPlayTarget` 聚合 `OnSorceryCast` 的 `Target` → `MatchesSpec` → `TargetValidity.CheckRestrictions`。单卡逻辑全在数据里。
3. **拖出弹窗选目标**：`Arena.BeginSorceryTargetSelection`（`Arena.cs`）——费用预校验（`GetAvailableMana` + `GetCostModification`，不足退回手牌）、收集候选（AreaZone + AttachedZone + CouncilZone）、无候选退回、确认后回调 `PlayCard`。
4. **弹窗原子锁**：`TriggerInteractionCoordinator.RequestActivateTargetSelection` 在开窗口时加 `ModalWindow.TargetSelection` 锁、`OnTargetPicked` 回调开头解锁（`IsInteractionLocked` 阻止同时激活其他效果）。JC012 / JC005 / JC014 机动 / JC002 进场统一复用。

## 五、制作一张新事务卡（快速行动）的标准步骤

以 JC005 为模板，照抄即可：

1. **新建卡牌 C# 脚本**：`Cards/Effects/PlayerCards/JC/新卡UID.cs`
   - 定义 `public static class 新卡UID_Effects`
   - `Register()` → `CardEffectFactory.Register("新卡UID", Build)`
   - `Build(PlayerCardData data)` 中 `data.EffectDataList.Add(new EffectData { ... })`，按需求填：
     - `Timing = EffectTiming.OnSorceryCast`（打出即结算）
     - `PlayTiming = PlayTiming.Response`（快速行动 C 档）
     - `Target = new TargetSpec { Kind = <目标大类>, NeedsSelection = true, Restrictions = <限制集合> }`
     - `Actions = new Array<EffectAction> { new EffectAction { Verb = <动作> } }`
     - `Duration = "瞬时"`
2. **注册进系列**：在 `JCEffects.RegisterAll()` 增加一行 `新卡UID_Effects.Register();`
   （全量注册 `AllEffects.RegisterAll` 与运行时 `GameInitializer` 已自动覆盖，无需再改。）
3. **`.tres` 资源**：只需在 `Cards/Data/PlayerCards/JC/新卡UID.tres` 填牌面基础信息（`CardName`、`CategoryFlag = 2` 即 Sorcery、`Effects` 文本描述等）。**效果不写在 `.tres` 里**。
4. **如需条件式目标**（如“有某领域才放宽范围”）：
   - 在 `TargetRule.cs` 增加枚举；
   - 在 `TargetValidity.cs` 的 `CheckRestrictions` 增加对应 `case`（取目标阶段评估）；
   - 若该限制只在取目标阶段生效、结算不复检，确保它被列入 `ExcludePlayTimeOnlyRestrictions` 的剔除集合（参考 `AttachedToCharacterIfNoMind`）。
5. **测试**：在 `Script/Tests/` 新建 `新卡UIDTests.cs`（继承 `TestRunner`），`SetUp` 调 `AllEffects.RegisterAll()`，用例覆盖取目标阶段 / 结算复检 / 边界；并把 `new 新卡UIDTests()` 加入 `Script/Tests/TestsRunner.cs` 的 runner 列表。

> 复用原则：**能写进 `EffectData.Target` + `TargetRestriction` 的，就不要拆多个效果或写判定代码**。JC005 的“单一效果 + `AttachedToCharacterIfNoMind`”即为范例。
