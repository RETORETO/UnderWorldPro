# 行动效果制作指南

> 现行有效版（2026-08-11）。旧文档 `行动效果制作流程.md` 保留历史 BUG 记录，本文件为清理后的可执行规范。
> 定位：激活（行动）效果制作规范。目标选取见《取单目标效果制作指南》。

---

## 一、行动效果定位

| 维度 | 说明 |
|---|---|
| 时机 | `EffectTiming.CharacterActivated`（角色激活）/ `AttachmentActivated`（附属激活）/ `CouncilActivated`（秘社激活） |
| 入堆叠 | ✅ 经 `EffectEngine.PushActivationToStack` 入栈（自动登记 `TargetVersionId`） |
| 激活窗口 | `ActivateWindow`（`string`）：`"快速"`（有优先权即可）/ `"行动"`（限自己行动步骤+堆叠空）/ `"触发"` |
| 门禁 | `ActivateEligibility` 预计算缓存（候选/横置/控制者/费用/合法性） |
| 费用 | `Cost`（`int`，费用数字）；横置/牺牲代价用 `ActivateCondition`（`string`，如 `"横置本角色"`/`"牺牲本角色"`） |

## 二、制作一个行动效果（数据驱动）

在**静态注册类** `Cards/Effects/PlayerCards/XX/卡名_Effects.cs` 的 `Build(PlayerCardData data)` 方法里，向 `data.EffectDataList` 填 `EffectData`，并经 `CardEffectFactory.Register("卡UID", Build)` 登记（详见《触发效果制作指南》§〇 新范式三件套）。效果由 `CardManager.CreateCardInstance` 内 `CardEffectFactory.EnsureEffects(data)` 按 `data.UID` 填充。

```csharp
private static void Build(PlayerCardData data)
{
    data.EffectDataList.Add(new EffectData
    {
        EffectId = "JC003_1_Tap",                  // 卡号_序号_动词
        Timing = EffectTiming.CharacterActivated,
        ActivateWindow = "快速",                    // "快速"/"行动"/"触发"
        ActivateCondition = "横置本角色",            // 横置/牺牲代价（字符串）
        Cost = 0,                                  // 费用数字（int）
        Target = new TargetSpec                    // 取目标见《取单目标效果制作指南》
        {
            Kind = TargetKind.Character,
            NeedsSelection = true,
            CanTargetSelf = false,
            IncludeCovert = true,                  // 或暗藏者
            Restrictions = new Array<TargetRestriction> { TargetRestriction.Enemy },
        },
        Actions = new Array<EffectAction>          // 结算动作序列
        {
            new EffectAction { Verb = ActionVerb.Tap },
        },
    });
}
```

### 关键字段
- **`Cost`**（`int`）：费用数字（"快速行动N"中的 N）。横置/牺牲代价用 `ActivateCondition`（`string`）表达，如 `"横置本角色"`/`"牺牲本角色"`/`"横置本角色,牺牲本角色"`；引擎通过 `ActivateCondition.Contains("横置本角色")` / `Contains("牺牲本角色")` 解析。**已支持激活能力 + `Cost>0` 付费**（行动窗门禁 + 支付结算）。
- **`ActivateWindow`**（`string`）：`"快速"`（有优先权即可，堆叠开放可响应插队）/ `"行动"`（限自己行动步骤+堆叠空）/ `"触发"`。引擎用 `Contains("行动")` / `Contains("快速")` 判定。
- **`Target`**：完整 `TargetSpec`；`IncludeCovert=true` 实现"或暗藏者"；`CanTargetSelf=true` 用于自身为目标。
- **`Actions`**：`EffectAction` 序列，`Verb`（`ActionVerb`）可选 `Tap`/`Untap`/`Destroy`/`Bounce`/`Move`/`Sacrifice`/`Gain`/`Lose`/`Attach`/`Seal`/`Pay`/`PrepareUpkeep`/`DealDamage`/`Draw` 等（完整见 `EffectAction.cs` 的 `ActionVerb` 枚举）。`EffectAction` 仅 `Verb` + `Args`（`Array<string>`）两字段。

## 三、门禁与候选（ActivateEligibility）

- 预计算缓存：合法候选目标集、`CanActivate`（横置/控制者/费用/合法性）。横置代价判定经 `ActivateCondition.Contains("横置本角色")`（无独立 `IsTapCost` 字段）。
- 已落地：暗藏者放宽（`IncludeCovert` 字段）、地区候选（`GetOtherCombatAreaUids`）、`Pay` 费用门禁。
- 复用 `CardManager.MatchesRule` 做静态合法性，与取目标文档 §二 步骤4 对齐。

---

## 四、行动门禁与回合阶段（现行规范）

> `ActivateWindow` 是 `string`（`"快速"`/`"行动"`/`"触发"`），**不是**回合阶段枚举。回合阶段由 `TurnManager.TurnPhase` 表达。

**激活窗口（`ActivateWindow` 字符串）门禁**：

| 值 | 可用时机 | 说明 |
|---|---|---|
| `"快速"` | 拥有优先权即可 | 堆叠开放时可响应插队（如 JC003/JC020） |
| `"行动"` | 限自己的行动步骤 + 堆叠为空 | 先手→`TurnPhase.ActionFirst`，后手→`TurnPhase.ActionSecond` |
| `"触发"` | 触发类效果 | 经触发排序窗口 |

**回合阶段（`TurnManager.TurnPhase`）**：`StartReset`（重置步骤）/ `StartPrepare`（准备）/ `StartDraw`（抓牌）/ `ActionFirst`（先手行动）/ `ActionSecond`（后手行动）/ 对抗步骤 / 结束步骤等。重置阶段流：`TurnManager` 按 `TurnPhase` 顺序推进（`StartReset → StartPrepare → StartDraw → ActionFirst → ActionSecond → …`）。

## 五、制作注意事项

- 横置/牺牲代价写 `ActivateCondition`（`string`），引擎 `Contains` 解析；`Cost` 仅存费用数字（`int`）。
- `Cost>0` 付费须在卡面标注金额（如"支付 2 费用"）。
- 测试自建 `StackManager` 须 `SetCardManager(cm)` 才能登记版本号（见取单目标文档 Q5）。
- **横置/重置一律走 `CardInstance.SetTapped(bool)`**（发 `TappedChanged` 事件），勿直接赋值 `IsTapped`，否则持续效果（如 JC068 阿格斯IV封锁）不同步。

## 六、特殊动作动词与强制选择窗

### 6.1 准备维护动词 `PrepareUpkeep`（JC068「阿格斯IV」）
```csharp
new EffectAction { Verb = ActionVerb.PrepareUpkeep, Args = new Array<string>{ "1" } }  // 支付1
```
- 语义：准备步骤"支付 N 费用，否则横置来源卡"。
- 链路：`EffectEngine.ExecuteVerb(PrepareUpkeep)` → 注入的 `EffectEngine.PromptPayOrTap`（Arena 注册）弹出二选一窗 → 玩家选择后回调统一调 `EffectEngine.ResolvePrepareUpkeep(source, N, pay)` 落地（`pay=true` 走 `PlayerManager.SpendMana`，`pay=false` 走 `source.SetTapped(true)`）；无 UI（测试）时兜底 `ResolvePrepareUpkeep(source, N, CanPayPrepareUpkeep(...))`。

### 6.2 强制选择窗 `ForceChoice`（`ActivationChoiceWindow`）
- `win.ForceChoice = true`：**不显示取消按钮 + 点窗口外不关闭**——玩家必须选一个选项才能继续。
- 用于强制触发效果（如阿格斯准备维护二选一）。默认 `false` 行为不变（可取消/点窗外关闭），不影响其他非强制选择。

### 6.3 激活生效区门禁（方案C：声明式生效区）
`ActivateEligibility.CanActivate` 内层 foreach 对每个激活效果用 `EffectEngine.IsEffectActiveInZone(e, card)` 判定：
- 默认：**附属卡仅 `AttachedZone` 可激活；角色卡仅 `AreaZone` 可激活**（`e.Scope` 未声明回退卡类型默认）。
- 显式声明 `Scope` 的激活效果按声明（如未来"手牌可发动""墓地可发动"）。
- 非对应区的激活效果被跳过，不可发动。

> 制作新激活效果：若需"非默认区激活"（如手牌/墓地），在该 `EffectData` 显式声明 `Scope`，无需改 `ActivateEligibility`。
