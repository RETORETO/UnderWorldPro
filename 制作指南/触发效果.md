# 触发效果制作指南

> 现行有效版（2026-08-11）。旧文档 `触发效果制作流程.md` 保留历史 BUG 记录，本文件为清理后的可执行规范。
> 定位：触发效果制作规范。目标选取见《取单目标效果制作指南》。

---

## 一、触发效果定位

| 维度 | 说明 |
|---|---|
| 时机 | `EffectTiming`：进场/离场/被横置/被翻面/受击/夺控/己方资产建立等（经总线事件） |
| 入堆叠 | ✅ 统一经 `TriggerRegistry.RunTriggerPhase` 排序窗口入栈（`PushTriggersToStack` 已删除，D36） |
| 排序窗口 | 同阶段多触发按 `TriggerPriority` 排序，由 `TriggerRegistry` 统一收集后一次性入栈 |
| 候选 | 进场/现身触发经 `TurnManager.GetLocalZoneTargets`（本地区）；非本地区按 `TargetKind` 收集 |

## 〇、制作范式总览（2026-08 效果架构迁移后）

> **架构变更**：卡片效果代码从"每张卡一个继承 `PlayerCardData` 的 Resource 类（`Cards/Script/PlayerCards/XX/卡名.cs` 构造函数）"迁移为"**静态注册类 + 统一工厂 `CardEffectFactory`**"（`Cards/Effects/PlayerCards/XX/卡名_Effects.cs`）。效果数据声明（`EffectData`/`EffectDataList`/`Timing`/`Target`/`Actions`）**逻辑不变**，仅承载位置与类形态改变。好处：不再为每张卡产生 Godot 资源类，启动/编译开销大降。

### 新范式三件套（每张有实现效果的卡）

**① 每卡一个静态注册类**（`Cards/Effects/PlayerCards/XX/卡名_Effects.cs`）：
```csharp
namespace Cards.Effects.PlayerCards.JC
{
    public static class JC002_jushizhenkanhuren_Effects
    {
        public static void Register()   // 用卡 UID 注册构建器（UID 与 .tres 的 UID 一致）
            => CardEffectFactory.Register("JC002_jushizhenkanhuren", Build);

        private static void Build(PlayerCardData data)   // 效果逻辑：改写 data 字段
        {
            data.EffectDataList.Add(new EffectData { /* ...见下... */ });
        }
    }
}
```

**② 系列聚合注册**（`Cards/Effects/PlayerCards/XX/XXEffects.cs`）：
```csharp
public static class JCEffects
{
    public static void RegisterAll()
    {
        JC002_jushizhenkanhuren_Effects.Register();
        // ... 本系列每张已实现卡一行
    }
}
```

**③ 顶层总注册**（`Cards/Effects/AllEffects.cs`）：发布/全量时调 `AllEffects.RegisterAll()`（依次调各系列 `XXEffects.RegisterAll()`），由 `GameInitializer.InitializeAll()` 在开局前统一调用。

> **`.tres` 不再绑定卡类**：所有 `.tres` 统一绑定通用 `PlayerCardData`（`script = ExtResource(...)` 指向 `PlayerCardData.cs`，头部 `script_class="PlayerCardData"`）。效果由 `CardManager.CreateCardInstance` 里的 `CardEffectFactory.EnsureEffects(data)` 按 `data.UID` 查表填充。空骨架/未实现卡（未注册）效果为空列表，等同旧"空构造函数"，不报错。

## 二、制作一个触发效果（数据驱动）

在**静态注册类的 `Build` 方法**里，向 `data.EffectDataList` 填 `EffectData`：

```csharp
private static void Build(PlayerCardData data)
{
    data.EffectDataList.Add(new EffectData
    {
        EffectId = "JC002_2_EntersArea",            // 卡号_序号_动词
        Timing = EffectTiming.EnterTrigger,         // 进场触发
        Target = new TargetSpec
        {
            Kind = TargetKind.Character,
            NeedsSelection = true,
            CanTargetSelf = true,                   // 含自身（JC002 进场选本地区角色）
            IsLocalZone = true,                     // 规则⑥本地区
        },
        Actions = new Array<EffectAction>
        {
            new EffectAction { Verb = EffectVerb.Tap, TargetMode = ActionTargetMode.EffectTarget, TargetRef = "T" },
        },
    });
}
```

### 关键字段
- **`Timing`**：见 §四 现行总线动词表。
- **`Target`**：完整 `TargetSpec`；本地区须 `IsLocalZone=true` + `CanTargetSelf=true`（若含自身）；候选为空时触发被跳过（见取单目标文档 Q3）。
- **`Actions`**：`EffectAction` 序列（同行动效果）。

### 强制触发（JC068「阿格斯IV准备维护」范式）
```csharp
var e = new EffectData
{
    EffectId = "JC068_A_Upkeep",
    Timing = EffectTiming.OnTurnStarted,   // 准备步骤强制触发
    Forced = true,                          // 强制：玩家不能放弃/拖入放弃区
    Scope = ZoneScope.AttachTarget,
    Actions = new Array<EffectAction> { new EffectAction { Verb = ActionVerb.PrepareUpkeep, Args = new Array<string>{ "1" } } },
};
data.EffectDataList.Add(e);
```
- **`Forced = true`**：表示强制触发，玩家**不能**在触发排序窗口把它拖入放弃区，也不能点"放弃剩余触发"跳过。
- **实现链路**：`TriggerRegistry` 收集 → `TriggerInteractionCoordinator` 构造条目时读 `t.EffectDataRef?.Forced` 传 `IsMandatory` → `TriggerOrderRoot` 阻止拖入放弃区 + Done 按钮禁用。
- 强制触发若带"二选一"动作（如支付/横置），弹窗需用**强制选择窗**（见《行动效果制作指南》§ForceChoice），玩家必须选一项才能继续。

### 触发源区域判定（方案C：声明式生效区）
- **角色卡**：默认仅 `AreaZone`（争夺区）可作触发源。
- **附属卡**：默认仅 `AttachedZone`（附属区）可作触发源。
- **统一判定**：`TriggerRegistry` 内层 foreach 对每个触发效果用 `EffectEngine.IsEffectActiveInZone(e, card)` 判定——`e.Scope` 未声明（`Specified`）走卡类型默认，显式声明按声明（如未来"墓地时触发""手牌时触发"）。
- 进场/现身例外（D40 规则1.6：仅触发来源卡自身）保留，勿与生效区判定混写。

> 制作新触发效果：若需"非默认区触发"（如墓地/手牌），在该 `EffectData` 显式声明 `Scope`（如 `Graveyard`），无需改 `TriggerRegistry`。

## 三、排序窗口与入栈（现行）

- 触发**不再**由各效果直接 `PushTriggersToStack`，统一由 `TriggerRegistry.RunTriggerPhase(phase)` 收集该阶段所有待触发、排序后一次性入栈。
- **排序规则（2026-09 校正）**：本项目**没有 `TriggerPriority` 字段**（旧的"按 TriggerPriority 排序"说法不成立）。
  实际顺序 = ① 按 `ControllerId` 分组；② 组序先手玩家优先、其余按 id 升序（`TurnManager.BuildTriggerOwnerGroups`）；
  ③ 窗口**内**顺序由玩家拖拽决定（单机 `TriggerOrderWindow` / 联机 `SelectTriggerOrder` 的 `SelectedIndices`）。
- 反应触发（反击）同理经排序窗口。
- 结算复检：`TurnManager` 入栈登记来源快照（`CaptureTargetSnapshot`，仅来源快照）+ `StackManager.Push` 统一登记 `TargetVersionId`；结算时 `TargetValidity.Check` + `EffectEngine.ValidateTargetAtResolve` 双路兜底。

### 3.1 "登记 ≠ 触发"（重要，2026-09 更新）

`TriggerRegistry.EventToTiming` 登记映射**不代表运行时会发事件**，必须在业务点 `Emit`。

**已接线（生产会真触发）**

| 时机 | 发点 |
|---|---|
| `EnterTrigger` / `UncoverTrigger` | `ZoneManager.MoveToArea`、**`MoveToAttachedZone`（P1 补：附属进场原先永不触发）**、`TurnManager.ResolveEntry` |
| `OnCardPlayed` | `TurnManager.PlayCard` 末段（**对所有卡类型**发，含事务卡） |
| `OnTurnStarted` / `OnTurnEnded` | `TurnManager.DoPrepare` / `DoCleanup` |
| `ManeuverTrigger` | `TurnManager.DoPreCombat`（整回合一次） |
| `OnCombatWon` | `CombatManager.ResolveWinner`（**仅战斗对抗**，调查/势力无广播） |
| `OnCardDied`（P1 新增） | `CardManager.HandleInstanceDeath` + `DestroyInstance`（"消灭"按死亡广播） |
| `OnAreaWon`（P1 新增） | `AreaManager.ResolveAreaWon`（计分后、送牌库底前） |
| `OnDraw`（P1 新增） | `TurnManager.DrawCardsForPlayer` / `DrawFromBottomForPlayer` |
| `OnMarkerPlaced`（P1 新增） | `AreaManager.AddPowerMark` + `CardManager.AddCounter` |
| `OnMove`（P1 新增） | `ZoneManager.MoveToArea`（**含争夺区→争夺区**）/ `MoveToAttachedZone` |
| `OnCardLeft`（P1 新增） | `ZoneManager.MoveToHand` / `MoveToDeck` / `MoveToScore`（仅"原本在场上"） |
| `OnDiscard`（P2 新增） | `TurnManager.DiscardCards`（**弃牌唯一出口**：手牌 → 墓地，逐张广播） |
| `OnSealed`（P2 新增） | `TurnManager.SealCard`（**封印唯一出口**：双向引用 + 进封印区 + 广播；经 `ActionVerb.Seal` 与检索去向`封印`两处调用） |

**仍未接线（写了不会触发，别踩）**

| 时机 | 需先做 |
|---|---|
| `OnCounter` | 反制/终止原语（尚未规划） |

> `OnDiscard` 上下文约定：`TriggeringPlayerId` = **弃牌者**（供"每当敌方玩家弃牌时"用谓词 `DiscardByEnemy`），
> `ContextCard` = 被弃的牌，`ExtraInt` = 本次弃牌动作的**总张数**（供"遏制X（X=此次弃牌数量）"）。

> `OnSealed` 上下文约定：`ContextCard`/`SourceCard` = **被封印的那张卡**（`sealing`），`TriggeringPlayerId` = 封印者
> （`sealing.ControllerId`），**`ExtraString` = 宿主卡 UID**（空串 = 封印于地区），`TargetAreaId` = 封印所在地区。
> 收集口径：`TriggerRegistry` 按"事件主体卡"匹配（`ctx.SourceCard == null || card == ctx.SourceCard`），
> 因此"每当**一张卡**被封印时"（不限定主体）用无来源写法即可，"当**某张卡**被封印时"以主体卡为条件。

> ⚠️ 两个**结构性死角**：① **以暗藏方式进场**的卡，自身进场触发会被默认 `TriggerCovertMode.FaceUp` 拦掉
> （需要时显式写 `CovertOnly/Either`）；② **争夺区→争夺区移动**（机动/夺控）不发 `EnterTrigger`（D37），
> "当此角色进入一个地区时"必须用 `OnMove`。

### 3.2 触发语义总纲（2026-09 定稿，写触发效果前必读）

**一句话**：**触发条件必须在"卡在场上（争夺区/附属区）"时满足；一旦满足，入堆叠与结算阶段不再有任何地区要求。**

由此推出的四条：

| # | 规则 | 实现 |
|---|---|---|
| 1 | **条件在场上满足** → 触发效果的生效区按"**触发那一刻**"判定，不看卡此刻在哪 | `TriggerContext.SourceZoneAtTrigger`；`IsEffectActiveInZone(e, card, zoneAtTrigger)`（判定为"实时区域 ∪ 触发时区域"，两种写法都成立） |
| 2 | **入堆栈/结算无地区要求** → 触发已成立后卡去哪都不影响（墓地/牌库/手牌均可继续结算） | 入栈与结算路径**不判区域**；旁观者只要"条件满足时在场"，其后离场也能响应 |
| 3 | **"本地区" = 触发条件满足那一刻来源卡所在的地区** | `TriggerContext.SourceAreaAtTrigger` → `StackEffectInstance.SourceAreaAtTrigger` → `GetLocalZoneTargets`（取候选）+ `CaptureTargetSnapshot`（结算复检基准） |
| 4 | **死亡是"行为"，不是"从场上进墓地"** | 统一入口 `CardManager.ResolveDeath(card, DeathCause{Damage/Destroy/Sacrifice}, destination)`：**先广播死亡、再按去向离场**；去向可被替代效果改写（回牌库/手牌），**死亡触发照常成立**——绝不能用"卡在墓地"当判据 |

**死亡语义细则（写死亡触发/消灭/牺牲类效果前必读）**

| 要点 | 说明 |
|---|---|
| 死亡原因（JC 包） | **伤害致死 / 消灭（Destroy）/ 牺牲（Sacrifice）** → 死亡；**回手、回牌库（Bounce、撤回、地区赢取送库底）→ 不是死亡** |
| 没死就没有死亡触发 | `CardManager.DamagePreventer`（伤害被**防止** → 不写伤害 → 无死亡）与 `CardManager.DeathPreventer`（死亡被**阻止**，如"不会因为 A 效果被消灭"）成立时不广播 —— **A 效果成功生效但卡没死 ≠ 死亡** |
| 灵体（JC 包定义） | **灵体＝防止伤害**：受到超过防御上限的伤害也不死 → **不产生死亡触发**。实现＝注册 `DamagePreventer`（P2） |
| 去向与死亡解耦 | `ResolveDeath(..., destination)` 的 `destination` 只决定卡去哪（默认墓地）。将来"所有卡不进入墓地、直接返回牌组"这类替代效果只改去向，**死亡触发照常成立** |
| 死亡触发写默认生效区 | 死亡在卡**离场之前**广播 → 生效区判定天然在场上成立；**不要**写 `Scope=Graveyard`（与 JC 包约定冲突） |
| 进场即死 | 进场触发窗口在"进场之后"打开，此时卡可能已在墓地 → 靠规则 1（触发时区域=进入的区）照常成立。顺序：`MoveToArea` 的 `FireMoved` 期间被持续效果消灭 → 随后才发 `EnterTrigger` |
| 正在死亡的卡不是目标 | `CardInstance.IsDying` 在死亡广播期间置位 → 候选收集（`GetLocalZoneTargets`/`LegalityProjection`）排除它 |
| 触发期间的"场上动作"护栏 | 触发已成立后来源可能已离场；`Move`/`Latent`/`Uncover` 会先校验"卡是否在场上"，避免把墓地/手牌里的卡搬回场上、翻面 |

> **包差异提醒**：以上是 **JC 卡包**的约定，**引擎本身更宽松**（`Scope` 两种写法都支持、触发收集按"实时 ∪ 触发时"区域判定）。
> 后续卡包若修改触发规则（例如允许"卡在墓地也能响应某事件"），只需改本包约定与用例 `TriggerSceneSemanticsTests`，**无需改引擎**。

> **"检索 ≠ 抓牌"（P2 口径）**：`Search`（"从牌库寻找一张…加入手牌"）**不广播 `OnDraw`**。
> `OnDraw` 的语义是"从牌库**顶**抽一张"（唯一收口 `TurnManager.DrawCardsForPlayer` / `DrawFromBottomForPlayer`，含初始发牌/回合抓牌/效果抽牌）。
> 若某卡文确实把"寻找并加入手牌"也算作抓牌（例如"当你抓牌时"覆盖检索），应在该卡自身用 `ExtraString` 显式区分，而不是放宽 `OnDraw` 的全局口径。

## 四、现行时机枚举表（制作时直接选）

> `EffectTiming` 枚举定义于 `Script/Data/Effects/EffectData.cs`，**新增时机一律追加在枚举末尾，禁止在中间插入**（保持整数顺序稳定）。

| 时机 | 写法（`EffectTiming`） | 触点 |
|---|---|---|
| 持续常驻（B组） | `Continuous` | `RegisterPersistent` 注册表 |
| 静止/禁止（B组衍生） | `Static` | 置位 `StaticFlags` |
| 进场触发（C组） | `EnterTrigger` | `GameEvent.EnterPlay`（`ZoneManager.MoveToArea` Emit） |
| 现身触发（C组） | `UncoverTrigger` | `GameEvent.Uncover`（`TurnManager.RevealCovert` 结算 / `CardManager.RevealCard` Emit） |
| 角色激活（C组） | `CharacterActivated` | `EffectEngine.ActivateAbility` |
| 附属激活（C组） | `AttachmentActivated` | `EffectEngine.ActivateAbility` |
| 机动触发（C组） | `ManeuverTrigger` | `GameEvent.PreCombat` |
| 事务卡打出结算（F组） | `SpellCast` | 打出即结算 |
| 反应：卡被打出 | `OnCardPlayed` | `GameEvent.OnCardPlayed` |
| 回合结束 | `OnTurnEnded` | `GameEvent.OnTurnEnded` |
| 回合开始（准备步骤） | `OnTurnStarted` | `GameEvent.OnTurnStarted` |
| 反应：卡死亡 | `OnCardDied` | `GameEvent.OnCardDied` |
| 赢取地区 | `OnAreaWon` | `GameEvent.OnAreaWon` |
| 抓牌 | `OnDraw` | `GameEvent.OnDraw` |
| 弃牌 | `OnDiscard` | `GameEvent.OnDiscard` |
| 放置指示物 | `OnMarkerPlaced` | `GameEvent.OnMarkerPlaced` |
| 被封印 | `OnSealed` | `GameEvent.OnSealed` |
| 场上移动 | `OnMove` | `GameEvent.OnMove` |
| 被终止 | `OnCounter` | `GameEvent.OnCounter` |
| 离场（非死亡） | `OnCardLeft` | `GameEvent.OnCardLeft` |
| 战斗对抗获胜 | `OnCombatWon` | `TriggerEmitPoints.CombatWon` |
| 秘社激活（C组衍生） | `CouncilActivated` | 秘社双击激活 |

> 事件→时机的映射登记于 `TriggerRegistry.EventToTiming`；**登记 ≠ 已触发**，业务点必须调用 `GameEventBus.Emit(对应事件)` 才会真正广播（部分时机【待接】，见各枚举注释）。

> 激活窗口（`ActionFirst`/`BeforeStart`/`StartReset`）是 `ActivateWindow` 字段（见《行动效果制作指南》§四），**不是 `EffectTiming`**。

## 五、已知坑

- 候选为空 → 触发跳过（不入栈）。本地区须 `CanTargetSelf=true` + `CardManager._zoneManager` 已注入（测试漏设则候选恒空）。
- 触发入栈走 `CaptureTargetSnapshot`（仅来源快照）+ `StackManager.Push`（版本号），无需手动登记。
- 多触发同阶段用 `TriggerPriority` 控制顺序。
