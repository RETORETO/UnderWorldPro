# 取单目标效果制作指南

> 现行有效版（2026-08-11）。本文只讲"选什么目标、目标何时丢失、本地区/敌我限制怎么加"。`Timing`/`ActivateWindow`/`Cost` 见触发/行动文档。
> 旧文档 `取单目标效果制作流程.md` 保留历史 BUG 记录，本文件为清理后的可执行规范。

---

## 一、目标系统速览（三类效果共用）

| 维度 | 说明 |
|---|---|
| 数据载体 | `TargetSpec`（`EffectData.Target`） |
| 目标种类 | `TargetKind`：`None`/`Character`/`Attachment`/`Asset`/`Council`/`Area`/`StackCard`/`Covert`/`Player`/`Seal`/`Deck`/`Graveyard`/`Hand` |
| 候选收集 | 进场/现身触发经 `TurnManager.GetLocalZoneTargets`（本地区）；行动经 `ActivateEligibility` 预计算缓存 |
| 合法性校验 | `TargetValidity.Check`（过程记忆快照）+ `EffectEngine.ValidateTargetAtResolve`（版本号比对 + `TargetRules` 属性二次复检） |
| 丢失处置 | 由 `TurnManager.ResolveEntryTargetIsLost` / `EffectEngine.ValidateTargetAtResolve` 按 `LossMode` 决定 |
| 版本号登记 | **统一收口于 `StackManager.Push`**：入栈时若注入 `CardManager` 且填 `TargetCardUid`，自动 `entry.TargetVersionId = 目标.VersionId` |

三类效果的目标字段写法一致；持续效果（B组）多数无需目标。

## 二、制作取单目标效果（数据驱动）

在**静态注册类** `Cards/Effects/PlayerCards/XX/卡名_Effects.cs` 的 `Build(PlayerCardData data)` 方法里，向 `data.EffectDataList` 填 `EffectData` 并在其 `Target` 字段写目标规则（经 `CardEffectFactory.Register("卡UID", Build)` 登记，详见《触发效果制作指南》§〇）：

```csharp
data.EffectDataList.Add(new EffectData { Target = new TargetSpec { /* 见下步骤 */ } });
```

1. **选种类** `Target.Kind`：`Character`/`Covert`/`Area` 等；"角色或暗藏者" → `Kind=Character` + `IncludeCovert=true`。
2. **需选择** `NeedsSelection`：需点选 `true`；自身/全体对象 `false`。
3. **可指定自身** `CanTargetSelf`：默认 `false`。
   ⚠️ **判据（2026-09 用户口径 A62，务必逐字核对卡文）**：**卡文没写"另一个"、也没用"敌方/其他"限定 ⇒ 必须设 `true`**。
   原因：`CanTargetSelf=false` 会把**源卡自己**排除出候选（`TurnManager.GetTargetUidsForSpec`：
   `if (inst == source && !canTargetSelf) continue;`）。若源卡**本身就是**卡文所述的目标类别（如 JC004 力场法师
   找"本地区的目标角色"、JC087 走私客找"本地区的目标本方角色"），那么当它是该范围里**唯一**合法对象时候选为空 ⇒
   整条效果被当作"**无合法目标**"处理：**触发静默跳过（不进堆叠、界面无提示）**、激活能力不可发动、事务卡打不出。
   · 已按此修复：JC004 / JC017 / JC087 / JC105 / JC055 / JC003 / JC019；
   · **不需要**设 `true` 的情形：源卡本身不是角色（事务卡/附属源——它们不参与角色候选）、卡文明确排除自身
     （"另一个"）、语义上不能指向自己（把自身结附/封印到自己、自身即代价、限定子类别而自身不属于该子类别）。
4. **加限制**：见下表（静态 + 变化类）。
5. **暗藏者放宽** `IncludeCovert`：仅放宽静态朝向合法，不阻止翻面丢失。
6. **过滤文本** `Filter`：自由文本（如 `已横置`），行动类 `ActivateEligibility` 解析；"或暗藏者"已由 `IncludeCovert` 字段承担（见步骤 5），勿再用 `Filter` 表达暗藏者。
7. **取目标范围**（2026-09 用户实测 JC017 后固化）：
   - **触发/激活路径默认只枚举"来源卡所在地区"**。卡文**没有**「本地区」限定（如 JC017"消灭目标角色上的所有敌方附属"）⇒ **必须** `AllAreas = true`，否则只能指定本地区角色（用户报"JC017 可以指定其他地区的角色，现在不能指定"）。取"全场"时用 `AllAreas`，取"本地区"时用 `IsLocalZone`，两者互斥。
   - **形态角色直接迁区**（2026-09 用户口径，JC027）：形态转换使"附属"成为角色时，用 `ZoneManager.MoveFormZone`
     把它**迁入争夺区**（刷新版本号、不发进场/移动触发、保持附属身份），撤销形态时**迁回附属区**。
     这样它天然出现在"目标角色"候选、地区统计与"对地区所有角色"的伤害里，**不需要**在取目标侧写任何补丁。
     配套两条引擎语义：① 声明为 `AttachTarget`（附属生效区）的能力/持续效果对"形态角色"（`CurrentZone==AreaZone && IsAttached`）
     继续生效；② `HasDefense` 认"实例当前防御"（获得 +N 防御力的卡必须能受伤/能被分配伤害）。
   - **"目标含自身"（`CanTargetSelf`）在激活路径同样生效**：候选枚举、`IsLegalActivateTarget`、`HasLegalTarget`（UI 置灰判据）三处必须同口径；否则"本地区唯一合法对象就是自己"时能力会被判"无合法目标"、UI 置灰且双击被 `CanActivate` 拦下（JC003/JC019 宿主独自在场即此坑）。

### 限制字段（`Restrictions` + `Param`，枚举 `TargetRestriction`）
| Restriction | 含义 |
|---|---|
| `Friendly` | 目标控制者 == 来源方 |
| `Enemy` | 目标控制者 != 来源方 |
| `LocalZone`（或 `IsLocalZone=true`） | 目标须与来源同 AREASLOT（规则⑥） |
| `StaticSubCategory` | 目标静态模板 `SubCategories` 含 `Param` |
| `CurrentSubCategory` | 目标当前实际 `SubCategories` 含 `Param`（含运行时授予） |
| `CardName` / `SubCardName` | 目标静态 `CardName`/`SubCardName` == `Param` |
| `NotStaticSubCategory` | 目标静态模板 `SubCategories` 不含 `Param`（"非某类别"） |
| `CostAtLeast` | 目标静态印刷费用 `Cost >= int.Parse(Param)` |

> ⚠️ 原 `ControllerChangedToEnemy/Friendly`、`SubCategoryGained/Lost` 等"结算前变化"类枚举**已删除（2026-08-11）**，其语义（控制者/子类别变化即判丢失）现由 **D16 版本号方案**统一覆盖——任何控制者/子类别变化都会 `BumpVersion`，配合 `StackManager.Push` 登记的 `TargetVersionId` 比对自动判丢失，无需单独声明。

**三道兜底链**（互补，卡数据无需单独声明登记）：
- 变化类快照：`TargetValidity.Check` 过程记忆（控制者/子类别变化）。
- 版本号比对：`StackManager.Push` 统一登记，`target.VersionId != 入栈值` → 丢失（覆盖移动/翻面/子类别授予撤销）。
- `TargetRules` 属性二次复检：`ValidateTargetAtResolve` 版本号通过后，用实时 `source.ControllerId` 对来源卡 `TargetRules`（`Enemy`/子类别/费用）重裁决，兜底"夺控换边不刷版本号"。

## 三、本地区效果（规则⑥ · `IsLocalZone`）

- **语义**：目标须与来源同 AREASLOT（含另一争夺区）。**只判目标**是否仍在该地区；来源（发动角色）离开发动地不再判丢失（效果发动后与发动角色分离）。
- **数据**：`Target = new TargetSpec { Kind=Character, NeedsSelection=true, CanTargetSelf=true, IsLocalZone=true }`
- **候选收集** `GetLocalZoneTargets`：`AreaManager.GetSlotIndex(Source.ZoneDetailId)` → 同 SLOT 全部争夺区 → `CardManager.GetAreaInstancesBySlot` → 按 `Kind` 过滤、排除自身（除非 `CanTargetSelf`）。
- **判定**：`TargetValidity.Check` 规则⑥，结算时 `target.ZoneDetailId != snapshot.SourceZoneDetailId` → 丢失。
- ⚠️ 争夺区→争夺区移动**不刷版本号**，本地区丢失只能靠快照判定兜住。

## 四、限定敌方 / 友方（控制者维度）

- **声明**：来源卡 `TargetRules` 写 `Enemy`/`Friendly`/子类别/费用。取目标期经 `CardManager.MatchesRule(rule, target, 来源当前控制者)` 裁决。
- **结算复检**（`ValidateTargetAtResolve`）：
  1. 版本号比对（覆盖会刷版本号的变化）。
  2. `TargetRules` 属性二次复检：基准用**实时 `source.ControllerId`**（非入栈快照）。夺控换边（目标敌→友）不刷版本号，靠此拦下 → 判丢失。
- 验证：`EffectStackTests.TestResolveRejectsTargetAfterControlTransfer`、`TestPushAutoRecordsTargetVersionId`。

## 五、已知坑

- **Q1** 测试构造 `CardInstance` 须显式设 `src.ControllerId`（默认 0 会使控制者变化判定失效）。
- **Q2** `IncludeCovert` 不阻止翻面丢失（翻面由 `CovertChanged` 总线判丢失）。
- **Q3** 候选为空 → 进场/现身触发被跳过（不入栈）。成因：`CanTargetSelf=false` 但本意含自身；`CardManager._zoneManager` 未注入；`CategoryFlag` 未声明 `Character`。
- **Q5** 测试自建 `StackManager` 须手动 `sm.SetCardManager(cm)`，否则版本号不登记。
- **Q6** 夺控换边不刷版本号，必须靠 `TargetRules` 属性二次复检兜底。

## 六、取目标效果在激活弹窗中的合法目标预判断（UI 收口）

行动类"取单目标"效果经通用激活弹窗（`ActivationChoiceWindow`）发动时，构建选项阶段即预判断场上是否存在合法目标，使无目标效果在弹窗里就置灰不可点：

- 对 `ability.Target is { NeedsSelection: true }` 的项，调 `ActivateEligibility.HasLegalTarget(source, ability, cardManager)`（public 查询入口，与 `IsLegalActivateTarget` 同源裁决）。
- 返回 `false` → 该项 `ActivationChoiceItem.Disabled = true`，label 追加"（无合法目标）"；`ActivationChoiceWindow.Init` 中按钮置灰且点击不触发 `OnChosen`。
- 该预判断是交互层收口；真实安全校验仍在发动落点：
  - 附属激活路径：`BeginAttachmentActivateWithTarget` 弹选目标窗前再用 `IsLegalActivateTarget` 实算合法 UID 集合，只传合法目标给 `RequestActivateTargetSelection`。
  - 角色卡拖拽路径：`CardDragController.EndActivateDrag` 落点经 `IsLegalActivateTargetCached`（读 Arena 预计算缓存）校验，非法落点取消发动。
- 逻辑集中在 `Arena.OpenAttachmentActivateChoice` 的 `abilities` 循环，自动覆盖所有走该路径的附属卡取目标效果；角色卡取目标效果走拖拽路径，无需此预判断。

> `HasLegalTarget` 为 `public static`；其裁决与 `IsLegalActivateTarget`（未配置 TargetRules 分支按 `ability.Target.Kind` + `IncludeCovert` 放宽暗藏者）同源。
