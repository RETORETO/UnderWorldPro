# 连续效果「层级计算」改造计划（照搬万智层序；只算四种基础属性）

> **口径（用户 2026-10-16 定稿）**：
> ① **直接照搬万智的层与计算顺序**；暂时用不到的层**留空占位给未来**；
> ② **不考虑控制权 / 魔法领域 / 类别**等（它们不是"属性计算"）；
> ③ **只做四种基础属性：调查 / 战斗 / 势力 / 防御**（＋对应的先手变体）；
> ④ **同一层级内的效果按"生效顺序"（时间戳）先后计算**；
> ⑤ **JC106 同等视为 7e（近似交换）**——虽然字面不是"交换"，但等价于"把某类图标整体换成另一类"，
> 故与未来的交换效果同层，**在最后施加**（永远看得见前面各层的全部结果）。
>
> **分层唯一判据**＝`Cards/Data/PlayerCards/JC/*.tres` 的 `Effects` **卡文措辞**（不是代码动词/字段）。
>
> **规则既定点（无争议）**：**能力图标即属性**——黑刀＝战斗、白刀＝先手战斗、黑眼＝调查、白眼＝先手调查、
> 黑星＝势力、白星＝先手势力（单一映射 `EffectEngine.IconToAttribute`）；**防御没有图标**，直接以属性表达。
> 【心】【血】【死】【星】等是**魔法领域图标**（另一条轴，本次不进层序）。
>
> 本文＝**层表 → 计算式 → 机制要求 → 影响面（要不要改卡）→ 现状缺陷 → 改动范围 → 验收锚点 → 待裁定**。

## 二、计算式（每张卡）

```
属性总值 = 印刷基准
  → 7a 定义值（本项目空）
  → 7b 设定 / 清零（JC028）
  → 7c 全部授予 / 剥夺，按生效顺序（时戳）施加：图标即属性、防御±N、光环、关键字、时效、动态份数
  → 7d 其他修正（本项目空）
  → 7e 交换 / 近似交换，**最后施加**：JC106（黑白星→黑刀）、JC123（失去黑白星）、未来交换效果
```

**先手变体**（先手调查/先手战斗/先手势力）与主属性同层同序计算，只是"仅当该卡控制者是先手玩家时计入总数"
（现状已如此：`AreaStatsCalculator.ValueOf`）。

**7e 在最后施加的意义**：改写**永远看得见 7c/7d 的全部结果** ⇒ 与"光环何时补授"无关：

| 情形 | 结果 |
|---|---|
| JC105 光环先在场 → JC106 后打出（替换） | **无白星、+1 黑刀** |
| JC106 先打出 → JC105 之后才在场（授予） | **无白星、+1 黑刀**（7e 最后跑，新授予的白星同样被改写） |

⇒ JC105×JC106 的"替换后白星复活"在层序上被根除；`TestB4_8A` 这条锚点在两种顺序下都应通过。

## 三、机制要求（照搬万智必须补的三件事）

| # | 要求 | 现状 | 说明 |
|---|---|---|---|
| ① | **每条连续效果/条目带"生效时戳"**（来源开始生效那一刻＝登记时刻），**重算不重新盖戳** | ❌ **没有时戳概念**（`_continuousRegistry` / `_auraGrants` 只有字典序，不可当顺序依据） | "同层按生效顺序"的前提；也是 7c 内多个授予之间可比的前提 |
| ② | **重算 = 从印刷基准按 (层, 时戳) 依次施加**，而不是"对当前数值做增量加减" | ❌ 现状＝增量（`Grant/Revoke` 直接改字段 + 自愈补授） | 增量会引入"何时补授"的顺序歧义 |
| ③ | **光环"自愈补授"必须沿用原时戳**（不是新盖一枚戳） | ❌ 现状：自愈判据＝"目标是否仍符合光环条件" ⇒ **把 7e 改写掉的图标补回来**（实测：替换后白星复活） | 万智语义：同一条静态异能只有一个时戳，重算不产生"新效果" |

## 四、影响面：**JC 范围内绝大多数效果不需要改动**

> 判据＝扫描 `Cards/Effects/PlayerCards/JC/*.cs` 的**持续/形态通道授予**（`ContinuousGrants` / `FormChangeSpec.Grants` / `MirrorSealedIcons`）。

| 项 | 数量 | 说明 |
|---|---|---|
| JC 卡脚本总数 | **135** | — |
| **落在四属性授予范围内**（持续/形态通道写 `Kind=Icon` 或 `Kind=Attribute`） | **21** | 占 16%；其余 **114 张完全不碰**（触发类、一次性动作、控制权/领域/类别/静止规则、费用修正…） |
| 其中**已一致、零改动** | **17** | 已按"图标 + 属性"或"仅属性但无对应图标（如防御）"正确书写 |
| 其中**卡文承诺图标却只写属性**（漏授） | **4** | JC018（［黑刀］）、JC030（［黑眼］）、JC085（［白星］）、JC060（［黑刀］——该卡已写【心】+战斗属性） |
| 持续通道**只写 Icon 没写 Attribute**（改造后数值会从 0 变正确＝隐藏缺陷） | **0** | ⇒ 折算收口**不会改变任何现有数值**，只让图标存在性判定变正确 |

**结论**：
- 若引擎做"**图标 ⇄ 属性双向折算**"（同一实现），则 **JC 卡脚本 0 改动**即可全绿；
- 若只做"图标 → 属性"单向折算，则需给 **4 张卡各补一行** `Icon:`（数值不变）；
- 其余 14 张"成对写 `Icon`+`Attribute`"的卡**不必改**（改造后 Attribute 那行成为冗余，删不删随意）；
- **必须改的只有引擎 4~5 处**（§五 P0）＋ 联机投影（P2）。

## 五、现状缺陷与改动范围

### 5.1 缺陷（可执行证据）

| # | 现象 | 根因 | 修法（层语义） |
|---|---|---|---|
| 1 | **4 张卡图标漏授**（JC018/JC030/JC060/JC085） | 图标与属性是**两套集合**，而三条通道只有两条自动折算：`Gain` ✅、`FormChangeSpec.Grants` ✅、**`ContinuousGrants` ❌** | **7c 写入收口**：一次写入同时成立（单一映射，双向） |
| 2 | JC105×JC106：`[白星]×1 → [黑刀]` 之后"仍有白星、没有黑刀" | 缺时戳 ＋ 改写作用于**数值**（基数混用）而非图标集合 ＋ 自愈按"条件仍成立"补授 | **§三①②③** ＋ JC106 移入 **7e**（最后施加、对象＝图标集合） |
| 3 | `P3ScaledGrantTests:121` 记着"图标授予**不**折进属性" | 两套账是**刻意**的历史兼容写法 | 同上（收口后该断言需按新口径复核） |

### 5.2 P0 — 最小可交付（建议先做）

| 项 | 改动点 | 规模 |
|---|---|---|
| ① 7c 写入收口 | `RegisterPersistent`（7535–7541）补折算，且**双向**（图标→属性、属性→图标）；三处折算收敛为同一实现 | 引擎 2 处 |
| ② 修 4 张卡 | JC018 补 `Icon:黑刀`、JC030 补 `Icon:黑眼`、JC085 补 `Icon:白星`、JC060 补 `Icon:黑刀`（**若①做双向折算则 0 改动**） | 卡脚本 ≤4（或 0） |
| ③ JC106 移入 7e | `ReplaceIcon` 改为"**对图标集合的整体改写**"，在**最后**施加：产出 `Icon:黑刀`、幂等、到期无损还原；`ReapplyIconSuppressions`（JC123）同口径、同层 | 引擎 1 处 |
| ④ 光环自愈判据 | 改为"**该条目（带原时戳）是否仍在 7e 之前的计算结果中生效**"，不再按"目标是否仍符合条件"补授 | 引擎 1 处 |
| ⑤ 防回归 | `JCContinuousGrantAuditTests`（卡文为判据）＋ `[KnownDefect]` 锚点 `TestB4_8A`（**已落地**） | 测试（已完成） |
| ⑥ 生效时戳 | 新增"连续效果生效时戳"（登记时分配、重算复用） | 引擎 1 处 |

### 5.3 P1 — 层序地基（零行为变更）

- 新增 `Script/Data/Effects/ContinuousLayer.cs`：层号（7a…7e）＋ 条目结构 ＋ `(层, 时戳)` 排序器；
- `EffectData` 增 `Layer`（默认由**卡文措辞**推导）；
- `EffectEngine` 增 `Recompute(card)` / `RecomputeAll()`，把现存 **E1–E5 五个重算入口**收敛为 1 个
  （`RegisterPersistent` / `UnregisterPersistent` / `ReevaluatePrereqs` / `ReevaluateAuras` / `ReapplyIconSuppressions`），
  并补掉审计发现的 4 处次序隐患。

### 5.4 P2 — 逐层落地 + 投影

- 四属性只由层序结果推导；`AreaStatsCalculator.ValueOf` 消费层序结果；
- **C/S 投影扩字段**（客户端不跑 `EffectEngine`：`GameSnapshot` / `RenderCommand` / `ZoneManager.ProjectCard` /
  `CardInstance.RestoreProjectedState` 必须带层序输出，否则两端不同解）。
