# 原子性规则（原子操作期间的玩家选择）——实现者清单

> **权威口径**：用户 2026-09 补充（全文见 `需求实现对照.md` §7.3.1）
>
> 「一个原子操作期间如果需要玩家选择，**玩家选择完成之前会阻塞进程**，直到玩家选择完成。完成前
> **只有持续效果可以影响游戏**，**无法加入新的行动效果/触发效果进入堆叠**。而**卡的打出（包括支付
> 费用、额外费用、确认忠诚等待）属于原子操作**，**卡的结算/效果的结算也属于原子操作**，都需要遵守
> 上面的规则。」
>
> 另见 `触发效果相关需求.txt` L172：原子操作＝地区赢取流程 2~5 步骤、**打出卡 / 结算卡 / 宣布使用
> 效果 / 结算效果**、3 种对抗过程。

---

## 〇、一句话规则

**只要一个原子操作里要玩家做选择，从开窗（或挂起）那一刻起就必须持原子锁；选择交付之前进程阻塞，
期间只能有持续效果生效。** 任何"新出牌 / 让过 / 激活 / 新触发入堆叠"都必须被拒绝。

---

## 一、原子操作清单（改代码前先对照）

| 原子操作 | 原子段起点 → 终点 | 谁负责持锁 |
|---|---|---|
| 打出卡牌 | 核心需求 7.1 第一步（确认忠诚）→ 入堆叠 + `OnCardPlayed` | `TurnManager.PlayCard`（`EnterAtomic` … `finally ExitAtomicWhenIdle`）＋ 前置选择窗的窗锁 |
| 结算卡牌 / 结算效果 | `ResolveStackTop`：`EnterAtomic` → `ResolveEntry` → 地区赢取检查 | `TurnManager.ResolveStackTop` ＋ 引擎挂起持锁 ＋ 选择窗窗锁 |
| 宣布使用效果（激活） | `EffectEngine.ActivateAbility`：开始改状态（付费/横置/牺牲/取牌作代价）→ 入堆叠 | `ActivateAbility`（`EnterAtomic` … `finally ExitAtomicWhenIdle`）＋ 激活前置选择窗的窗锁 |
| 对抗结算 ×3 | 调查 / 战斗 / 势力窗口 | `ModalWindowCoordinator` + `Arena.LockModal` |
| 地区赢取 2~5 步 | `AreaManager.TryStartAreaWin` | 归库顺序选择 UI 尚未实现（偏离 D1）；**实现时必须持锁** |
| 恢复步骤·手牌上限弃牌 | `DiscardToHandLimitAsync` | 整段 `BeginDecisionHold` … `finally EndDecisionHold` |
| 触发收集 / 排序窗口 | `RunTriggerPhase` → 排序窗 → 入栈 | `ModalWindow.TriggerOrder` + 选目标窗 |

## 二、三条实现通道（新代码照抄）

### 通道 1：单机 View 新增一个"要玩家选"的窗口

```csharp
// Arena 内：开窗 → 持锁；交付选择前 → 先解锁再调回调；无选择被关闭 → TreeExiting 兜底释放
LockChoiceWindow(win);          // ModalWindow.ChoiceBox + TurnManager.NotifyModalOpened
BindChoiceUnlock(win, items);   // 把每个 item.OnChosen 包成 "UnlockChoiceWindow(win); 原回调();"
win.PopupCentered();
```
- 取消路径**必须**交付一次回调（`ActivationChoiceWindow.OnCancelled` / 数值窗 `-1` / 预测窗"原序置顶"），
  否则挂起链悬空 + 持锁泄漏。
- **不要**在回调里直接改 Model 之前忘了先解锁：`PlayCard` / `ActivateAbility` 的入站门禁会因锁未释放而拒绝。

### 通道 2：引擎动作（`EffectAction` 动词）要玩家选

```csharp
SuspendChainForInput();                       // ＝登记续算点 + 进入决策持锁（TurnManager.BeginDecisionHold）
UIHooks.PromptXxx(..., res =>
{
    /* 落地 Model */
    ContinuePendingChain();                   // ＝整段流程完成后续算一次（内部配对释放持锁）
});
// 注意：若整段流程里还会再开第二个窗（如检索→结附宿主），只在**最后一个**回调里 ContinuePendingChain。
```
- 无 UI（headless / 纯规则内核）分支**不要**挂起，走确定性兜底即可。
- 同步回调桩（测试）会自动短路：`ContinuePendingChain` 清掉挂起标记 ⇒ 不产生挂起，行为与旧版一致。

### 通道 3：联机（服务端无 View）等待客户端回包

```csharp
await ee.HoldDecisionAsync(async () => { result = await ee.InputGateway.RequestChoice(pid, req); });
// 或 TurnManager 内部：await HoldAtomicDuringDecisionAsync(() => gateway.RequestChoice(...));
```
- 覆盖清单（已全部接入）：`EffectEngine.BeginGatewayFlow`（含搜索/弃牌/封印/可选支付/数字/牺牲选择等）、
  `RunTriggerPhaseAsync`、`ResolveCurrentAreaCombatAsync`、`ActivateAbilityWithChoicesAsync`、
  `PlayMultiTargetCardAsync`、`PlayWithExtraCostAsync`、`PlayModeCardAsync`、`RevealCovertWithExtraCostAsync`、
  **领袖 `LeaderRule`**、**道途 `PathRule`**、**遏制 `CurbRule`**、**预测 `PredictionRule`**、
  **JC119 免费打出取目标 `TurnManager.RequestFreePlayTargetAsync`**。
- 等待期间**不推快照**：候选必须随 `ChoiceRequest` 下发（`OptionUids` + `OptionCardRefs`）。

## 三、自检清单（提交前逐条打勾）

- [ ] 原子期间 `Pass` / `PlayCard` / `ActivateAbility` 三者都会被拒（日志出现 `⛔ 原子操作进行中`）。
- [ ] 选择窗**恰好交付一次**回调（选中 / 取消 / 点窗外 / 关闭窗口四条路径全覆盖）。
- [ ] 引擎挂起：**后续动作在玩家选择之前不得执行**；续算**只发生一次**（含"续算中又发起一次决策"）。
- [ ] 持锁与释放在 `try/finally`（或计数 + 幂等释放）中严格配对；异常路径不泄漏。
- [ ] `Reset()` / 换局后 `IsAtomicLocked == false`（防跨局锁死）。
- [ ] 新增通道有 headless 行为单测（参考 `Script/Tests/P3AtomicDecisionLockTests.cs`）。

## 四、反例（这些写法都曾真实出过 BUG）

| 反例 | 症状 |
|---|---|
| 只 `Show()` 窗口、不通知规则层 | 结算中途还能再出牌/再激活/让过，堆叠顺序被破坏 |
| 只开窗不 `SuspendChainForInput()` | 效果的后续动作**先于**玩家选择执行（顺序倒置） |
| 取消时窗口不回调 | 动作链永久悬空（后续动作丢失）＋ 持锁泄漏 ⇒ 整局卡死 |
| 用布尔锁表示"等待中"，并在窗口关闭时无条件解锁 | 内层窗关闭把外层持锁掀掉（多目标逐槽 / JC081 多选重叠时必现） |
| `EnterAtomic()` 之后仍有 `return` 而未解锁 | 一次失败出牌后双方永久无法让过 |
