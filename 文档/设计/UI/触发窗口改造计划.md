### 最终语义（"取消" vs "否定"）

| 环节 | 玩家动作 | 结果 |
|---|---|---|
| 取目标（卡/地区/玩家目标、区域牌堆选牌） | **取消** | 不入堆叠，**保留在排序窗口**（可重新双击/全部入堆叠；批量中则整体中止并回滚已预选目标） |
| 选择一项（K16 模式） | 取消（不打出） | 该效果不发动，**从窗口移除**（已了结） |
| 可选支付 / 二选一确认（K11） | 不支付 / 否 | 该效果不发动，**从窗口移除**（已了结）——见下方"为什么不给这两个也做留窗取消" |
| 无合法目标 | — | 该效果不入堆叠，**从窗口移除**（同上） |

**为什么可选支付/二选一不"留在窗口"**：它们的"否定"是效果自身可选费用的**了结**（"你可以支付N，否则不发动"），留窗只会让玩家反复看到同一个无信息量的选择；且强制触发 + 需付费时会让「放弃剩余效果」永久置灰（窗口锁死）。取目标不同：它没有"效果自身条件"的含义，只是入堆叠动作的一部分，留窗才能让玩家改主意或改用「全部入堆叠」。

### 未做（明确超出本次范围）
- 联机窗 `OnlineTriggerOrderWindow` 仍是双区设计（本轮只改单机）；共享组件已做 null 容忍，联机行为不变。
- 批量"全有或全无"只覆盖**取目标**；模式/支付/玩家目标/牌堆选牌的否定仍是"逐条了结"，可能产生部分入堆叠（与既有单条口径一致）。
- 双击/放弃均按原需求"不可撤销"，未加二次确认。

## 0. 摘要

| | |
|---|---|
| **现状** | 「双区拖拽」式：上方 `OrderZone`（入堆叠区）+ 下方 `DiscardZone`（放弃区），条目在两区间拖拽；按钮是「第一张进入堆叠」+「完成排序并放弃下方效果」。**没有双击交互。** |

### 三个必须先拍板的发现

**① 「全部入堆叠」按钮现在不存在。**
早期版本有过 `TriggerOrderWindow.OnAllEnterPressed`（见 `需求实现对照.md:1356`），后续重构中被下线；联机侧测试 `Script/Tests/NetChoicePanelTests.cs:332` 有一条**反向断言**：

```csharp
Assert.IsNull(win.GetNodeOrNull("RootControl/Panel/AllEnterButton"),
    "「全部进入堆叠」按钮已下线（场景中不应再有该节点）");
```

该断言的对象是**联机窗** `OnlineTriggerOrderWindow.tscn`。只要新按钮只加在单机窗，这条测试不受影响；但如果确认要同时改联机窗，**必须同步改这条断言**。

**② 目标选择窗「没有取消出口」——这是本需求最大的现状缺口。**
`TriggerInteractionCoordinator.RequestTargetSelection` 打开选目标窗时 `extraLabel = null`，导致 `TargetSelectionWindow.Open` 把确认键设成：

```csharp
ConfirmButton.Disabled = !hasExtra;            // = true，恒不可点
ConfirmButton.Text = hasExtra ? extraLabel : "（点场上卡后自动关闭）";
```

也就是说，单选取目标时玩家**必须点中一个合法目标**才能离开窗口（既无取消按钮，也没接 `close_requested`）。
⇒ 需求 §4 的「如果任意一个效果选择了『取消发动 / 取消选择』→ 中止整个批量操作」这一分支，**在现状下不可能被触发**；验收用例 6「中途取消一次」也就无从验证。
⇒ 要让该分支成立，必须**新增一个取消出口**。这是纯 UI 改动，可复用代码里**已经存在但未被触发路径使用**的 `extraLabel` / `OnExtra` 机制（K15 已在激活路径用过）。

**③ `ITriggerView.OpenTriggerOrderForPlayer` 有约 60 处实现（45+ 个测试桩文件）。**
直接给接口签名加参数（例如再加一个 `onEnterAllStack`）会波及全部测试桩。
⇒ 批量入堆叠必须走「**新增一个可选接口**」的薄封装路线，而不是改既有签名。

## 3. 推荐方案（方案 A）

### 3.1 场景结构改造（`Scenes/UI/TriggerOrderWindow.tscn`）

```
TriggerOrderWindow (Window 840×520)          ← 空间收紧（原 620 高）
├─ RootControl (Control, TriggerOrderRoot)
│  ├─ BlockLayer (ColorRect 遮罩)
│  └─ Panel
│     ├─ DragHandle                       ← 保留（整窗拖动）
│     ├─ TitleLabel      "触发效果排序"
│     ├─ HintLabel       "双击效果加入堆叠；也可『全部入堆叠』或『放弃剩余效果』。"
│     ├─ EntryListPanel (Panel)
│     │  ├─ EntryListLabel   "待排序触发（左→右 ＝ 先→后入堆叠）"
```

**删除**：`DiscardZone` / `DiscardZoneLabel` / `DiscardZoneContainer` / `FirstEnterButton`。

**导出字段调整**：

| 字段 | 处理 |
|---|---|
| `OrderZoneContainer` | 保留（指向 `EntryListContainer`），语义变为「唯一列表」 |

### 3.2 交互实现（`TriggerOrderWindow.cs`）

**核心状态机**：把「按钮可用性」收成一处计算，避免散落的 `Disabled = ...`。

```csharp
private bool _externalEnabled = true;   // 选目标/批量期间由协调器置 false
private bool _busy;                     // 单条入堆叠在途
private bool _batchInProgress;          // 批量在途
private bool _opened;                   // Open() 之后才允许自动关窗

private void ApplyButtonStates()
{
    bool on = _externalEnabled && !_busy && !_batchInProgress;
    bool hasEntries = EntryCount > 0;
    bool anyMandatory = AnyMandatory();
    if (AllEnterButton != null) AllEnterButton.Disabled = !on || !hasEntries;
    if (DoneButton     != null) DoneButton.Disabled     = !on || !hasEntries || anyMandatory;
    _root?.SetDragFrozen(!on);
}

public void SetButtonsEnabled(bool enabled)   // 名字不变（协调器既有调用点不动）
{
    _externalEnabled = enabled;
    ApplyButtonStates();
}

private bool AnyMandatory()
{
    foreach (var c in OrderZoneContainer.GetChildren())
        if (c is TriggerEntryUI t && t.IsMandatory) return true;
    return false;
}
```

**① 双击入堆叠**（`_Input` 内插一层命中判定，拖拽逻辑保持原样）

```csharp
if (@event is InputEventMouseButton mb && mb.ButtonIndex == MouseButton.Left)
{
    if (mb.Pressed)
    {
        if (_batchInProgress || _busy || !_externalEnabled) return;   // 重入闸
        var hit = _root.PickEntryAt(globalMouse);                     // PickEntryAt 由 private → public（仅可见性）
        if (mb.DoubleClick && hit != null)                            // ★ 双击＝入堆叠
        {
            OnEntryDoubleClicked(hit);
            GetViewport().SetInputAsHandled();
            return;                                                    // 不再走 BeginEntryDrag
        }
        if (_root.BeginEntryDrag(globalMouse)) GetViewport().SetInputAsHandled();
    }
    ...
}

private void OnEntryDoubleClicked(TriggerEntryUI entry)
{
    _busy = true;
    ApplyButtonStates();                                   // 冻结按钮与拖拽
    GD.Print($"[TriggerOrderWindow] 双击入堆叠: {entry.NameLabel?.Text}");
    // 复用既有单条通道：需选目标则由引擎弹原选目标窗，选完再入栈
    OnEnterStack?.Invoke(new List<object> { entry.TriggerData });
}
```

> 无需为「是否需要选目标」在 UI 侧做任何判断——`OnEnterStack` → `PushOrderedTriggers([t],0,onDone)` → `EnsureTriggerModeThenPush` → `EnsureTargetThenPush` 已经是完整原逻辑。
> 无需目标的触发会**同步**走完并立刻回填 `RemoveEntries`，手感即「双击立刻入堆叠」。

**② 全部入堆叠**

```csharp
private void OnAllEnterPressed()
{
    if (_batchInProgress || _busy || EntryCount == 0) return;
    var ordered = CurrentOrderedStackEffects();            // 按列表左→右顺序取 TriggerData
    if (ordered.Count == 0) return;

    if (_enterAllHandler == null)                          // 未装配批量能力 → 不静默吞击
    { GD.PrintErr("[TriggerOrderWindow] 未装配批量入堆叠处理器 → 忽略本次点击"); return; }

    _batchInProgress = true;
    ApplyButtonStates();                                   // 冻结（含拖拽，防批量期间改顺序）
    _enterAllHandler(ordered, pushedAny =>
    {
        _batchInProgress = false;
        if (!pushedAny) ApplyButtonStates();               // 中止：保留全部条目，恢复按钮
        // 成功：引擎已回填 RemoveEntries → 列表空 → 自动关窗（见 ④）
    });
}
```

**③ 放弃剩余效果**

```csharp
private void OnDonePressed()
{
    if (_batchInProgress || _busy) return;
    if (EntryCount == 0) return;          // 空列表本应已自动关窗
    if (AnyMandatory()) return;           // 双保险：有强制则置灰（UI 层）
    GD.Print("[TriggerOrderWindow] 放弃剩余效果");
    Close();                              // → Hide() + OnDone → TurnManager.processNext（★原逻辑不变）
}
```

> **底层未改**：放弃语义仍然只是「不把这些触发压入堆叠 + 关窗推进到下一个 owner 窗口」，与现状「点 Done 关窗」完全同一条路径。

**④ 自动关窗**

```csharp
private void TryAutoCloseIfEmpty()
{
    if (!_opened || _batchInProgress || _busy) return;
    if (EntryCount > 0) return;
    GD.Print("[TriggerOrderWindow] 列表已空 → 自动关闭");
    Close();                               // → OnDone → processNext
}
```

调用点：`Setup` 末尾（开窗兜底）、`RemoveEntries` 末尾（入堆叠回填后）。
`_opened` 在 `Open()` 内置 true、`Close()` 内置 false；`SetRemainingTriggerCount` / `UpdateRemainingTriggerCount` **保留但不再作为关窗门槛**（只打诊断日志），这样协调器/Arena 的既有调用点无需改动。

**⑤ 按钮状态汇总表**

| 按钮 | 可点击条件 | 备注 |
|---|---|---|
| 双击条目 | `_externalEnabled && !_batchInProgress && !_busy` | 拖拽同为该闸 |
| 全部入堆叠 | 同上 **且** 列表非空 | 有强制也**允许**（强制只禁放弃） |
| 放弃剩余效果 | 同上 **且** 列表非空 **且** 无强制 | 有强制 → 置灰 |

### 3.3 批量预选的接线（薄封装，不动 `ITriggerView` 签名）

**问题**：批量必须「先全量预选目标、再统一入堆叠」，而预选需要引擎才知道的信息（哪些触发要选目标、合法候选是谁）。这些是 `TurnManager` 的私有逻辑（`NeedSelectAnyTarget` / `GetValidTargetUidsForTrigger`）。

**做法**：新增一个**可选接口**，只由协调器实现；`TurnManager` 用 `is` 判定，未实现者（60 个测试桩）**行为完全不变**。

**新增 `Script/Interfaces/ITriggerBatchView.cs`**

```csharp
/// <summary>【触发排序·批量入堆叠】可选视图能力。
/// 与 ITriggerView 分离：未实现本接口的视图（测试桩 / headless）自动回退到既有单条路径，行为不变。</summary>
public interface ITriggerBatchView
{
    /// 注入「全部入堆叠」处理器（由 Controller 提供）。
    /// handler(ordered, onFinished)：ordered = 窗口内当前顺序；onFinished(pushedAny) 必被调用一次。
    void SetBatchEnterHandler(Action<List<StackEffectInstance>, Action<bool>> handler);

    /// 批量预选目标：在既有选目标窗基础上追加「取消」出口。
    /// onPicked(uid) = 选定；onCancelled() = 玩家取消 → 批量整体中止。
    /// 返回 false = 视图不可用（调用方应整体回退）。
    bool RequestBatchTargetSelection(StackEffectInstance trigger, List<string> validTargetUids,
        Action<string> onPicked, Action onCancelled);
}
```

**`TurnManager` 侧新增（只增不改）**

```csharp
/// 全部入堆叠：先按顺序为需要选目标的效果预选目标（任一取消 → 整体中止，一条都不入堆叠）；
/// 全部成功后调用既有 PushOrderedTriggers 统一入堆叠（此时目标已选定，自动跳过选目标）。
private void PreSelectTargetsThenPushAll(ITriggerBatchView bv, List<StackEffectInstance> list,
    Action onPushed, Action onAborted)
{
    int i = 0;
    void Step()
    {
        while (i < list.Count)
        {
            var t = list[i++];
            if (!NeedSelectAnyTarget(t) || !string.IsNullOrEmpty(t.SelectedTargetUid)) continue;
            var spec = t.EffectDataRef?.Target;
            if (PlayerTargetPool.IsPlayerSpec(spec)) continue;                                  // 玩家目标：沿用既有单条口径
            if (TargetZonePool.IsZonePileSpec(spec) && !TargetZonePool.IsFieldVisibleSpec(spec))
                continue;                                                                        // 区域牌堆（列表窗）：沿用既有单条口径
            var valid = GetValidTargetUidsForTrigger(t);
            if (valid.Count == 0) continue;                                                       // 与 EnsureTargetThenPush 同口径
            bv.RequestBatchTargetSelection(t, valid,
                onPicked:    uid => { t.SelectedTargetUid = uid; Step(); },
                onCancelled: () => onAborted?.Invoke());
            return;                                                                               // 等玩家选完再继续
        }
        PushOrderedTriggers(list, 0, onPushed);                                                   // ★ 复用既有入堆叠链路
    }
    Step();
}
```

**`RunTriggerPhase` 接线（3 行）**

```csharp
if (_view is ITriggerBatchView bv)
    bv.SetBatchEnterHandler((ordered, onFinished) =>
        PreSelectTargetsThenPushAll(bv, ordered,
            onPushed:  () => { _view.RemoveOrderEntries(ordered); onFinished?.Invoke(true);  },
            onAborted: () => onFinished?.Invoke(false)));

_view.OpenTriggerOrderForPlayer(owner, byOwner[owner],
    onEnterStack: ordered => PushOrderedTriggers(ordered, 0, () => _view.RemoveOrderEntries(ordered)),
    onDone: processNext);
```

**`TriggerInteractionCoordinator` 侧**

- 实现 `ITriggerBatchView`。
- `SetBatchEnterHandler` 只存字段；`OpenTriggerOrderForPlayer` 里把窗口的 `OnEnterAllStack` 接到它：

```csharp
_triggerOrderWindow.OnEnterAllStack = ordered =>
{
    if (_batchEnterHandler == null) return;
    _batchSelectMode = true;                       // 让选目标窗带「取消」出口
    _batchEnterHandler(ordered, pushedAny =>
    {
        _batchSelectMode = false;
        _triggerOrderWindow.SetButtonsEnabled(true);   // 收尾解冻（窗口自身按 _batchInProgress 复算按钮）
    });
};
```
- **抽取公共部分**：把 `RequestTargetSelection` 里「算提示语 → 高亮合法目标（卡/地区）→ 开窗 → 加模态锁 → 注册回调 → 清理」抽成私有 `BeginTargetSelection(trigger, valid, extraLabel, onPicked, onCancelled)`；`RequestTargetSelection` 与 `RequestBatchTargetSelection` 都调它，**单条路径的行为逐字不变**（只多传 `extraLabel: null`）。
- 批量模式下 `BeginTargetSelection` 传 `extraLabel = "取消（放弃全部入堆叠）"`，并把 `_targetSelectionWindow.OnExtra` 指向 `onCancelled`。
- 批量期间**跳过** `SetButtonsEnabled(false)` / 收尾的 `SetButtonsEnabled(true)`（窗口已由 `_batchInProgress` 自行冻结），避免中途解冻。
- 中止时由 `onFinished(false)` 收尾：不改窗口条目、恢复按钮。

**时序**

```
窗口「全部入堆叠」 → coord.OnEnterAllStack(ordered)
  → TurnManager.PreSelectTargetsThenPushAll
      → bv.RequestBatchTargetSelection(t1) → 选目标窗（带取消）→ 选定 → t1.SelectedTargetUid
      → bv.RequestBatchTargetSelection(t2) → ...
         ├─ 取消 → onAborted → onFinished(false) → 窗口保留全部条目、按钮恢复（★ 一条都没入堆叠）
         └─ 全部成功 → PushOrderedTriggers(list,0,RemoveOrderEntries) → 列表空 → 自动关窗 → processNext
```

### 3.4 「取消」出口的两种落点（需拍板）

| | 落点 | 影响 |
|---|---|---|
| **A（推荐）** | 仅**批量模式**的选目标窗追加「取消（放弃全部入堆叠）」按钮 | 单机双击路径与现状完全一致；需求 §4 的取消分支可实现；改动最小 |
| B | 单条路径也给选目标窗加「取消（不加入堆叠）」 | 双击带目标的效果也能取消 → 该条不入堆叠、列表保留该条。语义更完整，但**改变了现状交互**（原来必须选） |

两种都用既有 `extraLabel` / `OnExtra` 机制，不新增底层规则。B 若采用，需同时在 `TurnManager.PushOrderedTriggers` 的目标回调里加一条「`uid` 为空 → 跳过该条不入堆叠」的判定（**这是唯一需要碰的引擎侧分支**，属"薄封装"范畴，不改变入堆叠规则本身）。

### 3.5 与联机窗口的关系

- `OnlineTriggerOrderWindow` 是独立场景 + 独立脚本，改单机窗**不会**自动影响它。
- 但二者**共用** `TriggerEntryUI` / `TriggerOrderRoot`。⇒ 改共享组件必须同时验证联机。
- **硬约束**：`TriggerOrderRoot` 的 `DiscardZoneContainer` 必须容忍 `null`（`Setup` / `ArrangeOrderZone` 里目前是 `new[] { OrderZoneContainer, DiscardZoneContainer }` 直接遍历，**会 NRE**）。联机窗仍传非空容器 → 行为不变。
- 建议：本轮只改单机；联机窗列为后续（若一并改，需同步 `NetChoicePanelTests.cs:332` 的反向断言）。

## 6. 风险与回归点

## 7. 待拍板问题

1. **联机窗是否一并改？** 建议：本轮只改单机（`TriggerOrderWindow`），联机窗列为后续；共享组件只做「null 容忍」的兼容性改动。
2. **「取消」出口的落点**：A 仅批量模式可取消（推荐、最小改动）；B 单条双击也可取消（语义更完整，但改变现状交互）。见 §3.4。
3. **「全有或全无」的范围**：仅覆盖目标选择（推荐，与术语「预选择目标」一致），还是要把 K16 模式 / K11 支付 / K24 玩家目标 / 区域牌堆目标也纳入预选？（后者改动更深）
4. **列表排布**：是否加自动换行？（触发数多时会溢出）
5. **是否保留拖拽排序**？目标（双击＋全部入堆叠）下顺序仍决定入堆叠先后，建议保留。
6. **「放弃剩余效果」是否要二次确认？** 原需求写着「点下后不可撤销」，可选加一个确认弹窗。
7. **「无合法目标」的条目**：按现有口径它会被静默跳过（不入堆叠）且从列表消失。是否要在 UI 上给出提示（如灰显/标记）？

## 8. 备选方案（不推荐，列出供对比）

**方案 B：零接口改动的「贪心批量」**
`全部入堆叠` 直接把整份列表丢给既有 `onEnterStack` → `PushOrderedTriggers(list,0,...)` 逐条选目标即入栈。
- 优点：**完全不碰 TurnManager / 接口**，纯 UI 改动。
- 缺点：① 不满足「不产生部分入堆叠」；② §4 的取消分支无法实现（预期验收用例 6 无法通过）。

**方案 C：改 `ITriggerView` 签名加 `onEnterAllStack` 参数**
- 优点：接线最直白。
- 缺点：**波及 60 处实现 / 45+ 测试文件**，机械改动量最大、回归风险最高。**不推荐。**
