## 四、关键技术决策

### 决策 1：卡牌尺寸 140×196

- 由 100×140 放大到 **140×196**（1.4x，宽高比 5:7 保持不变）。
- **依据**：横向 3 地区 × 3 张 = 3×(140×3 + 间距) ≈ 1440px + 槽间距 < 1920，满足"3 地区每区 3 张 + 余量"。
- **常量收口**：`CardLayoutHelper.CARD_WIDTH/CARD_HEIGHT` 为唯一来源。**该常量已存在**  
  （`CardLayoutHelper.cs:15-16`，值 100/140，联机 `ArenaOl.cs:2161` 等已在引用），  
  本次工作是把**其余三处硬编码副本**改为引用它，共**四处**：
  - `CardLayoutHelper.cs:15-16`（`CARD_WIDTH=100` / `CARD_HEIGHT=140` —— **唯一真相源，只改这里**）
  - `Arena.Layout.cs:22-23`（`private const CARD_WIDTH = 100` / `CARD_HEIGHT = 140`）
  - `CardUI.cs:518-520`（`private const CARD_WIDTH = 100f` / `CARD_HEIGHT = 140f`）
  - `Scenes/UI/CardUI.tscn:7/10/11`（`custom_minimum_size = Vector2(100, 140)` / `offset_right = 100.0` / `offset_bottom = 140.0`）
- `AreaSlot.cs:111-112`（`cardWidth=140, cardHeight=100`）是**地区卡横条尺寸，语义不同**，见 6.6。

### 决策 2：争夺区纵向空间重排

- **现状**：`AreaSlot` 设计 400×580（`Scenes/UI/AreaSlot.tscn:11-12`），内部  
  `Player1Area`（y 0→240，`:60-61`）/`Player2Area`（y 340→580，`:32-34`）各约 240px 高（为封印/附属上下偏移预留），  
  中间 `CardContainer`（地区卡）140×100。
- **改造**：③ 折叠封印/附属后，上下区域不再需要为大偏移预留 → 按"一张放大卡 + 小余量"重设（约 200px）。
- **`ArrangeAreas()`**（`Arena.Layout.cs:413`）的 `slotWidth=400/slotHeight=580/spacing=30` 按新预算重算；槽宽需 ≥ 3 张放大卡宽度（140×3 + 间距 ≈ 480px）。
- **地区卡（AreaCardUI）** 尺寸与 `AreaSlot.cs:111` 的 `cardWidth/cardHeight` 同步。

### 决策 4：资产/分数区层叠紧凑 + hover 展开

- **层叠算法**：新增层叠布局（固定露边宽度 step，如每张露 36px），卡图保留（露出部分可见卡色）。
- **hover 展开**：复用同一浮层机制显示完整卡图。
- **双端**：`ArenaOl.RebuildAssets`（`:1825`）/ `RebuildAssetsInto`（`:1831`）/ `RebuildScoreZone`（`:2194`）同步。
- **层叠态下的候选/选中高亮（新增约束）**：选卡方案 3.4/4.5 要求"凡有场上 UI 的候选卡都高亮、选中态加绿框"。  
  层叠后每张只露 36px，黄框/绿框会被后一张压住 ⇒ 必须**专为层叠态定义呈现**，二选一：
  - **位移 + 抬层**：候选/选中时该卡向未覆盖方向位移并抬到层叠最上层（仅视觉偏移、不改数据）；
  - **角标指示标记**：在该卡露边区域追加候选/选中指示标记。  
    **两者取一，且不得复用/改动 `SetSelectableHighlight` 黄框接口**（与 8.5 描边语义分离一致）。

> ⚠️ **取目标语义（已定）**：资产属**无条件 cat-2** ⇒ 取目标一律走 `CardPickWindow`，**不做"原地悬浮直接选中"**。层叠后的 **hover 展开面板可点**，出口＝`CardPickWindow.SelectByUid`（等效点选择窗内该卡，**不直接提交**）；**未展开（仅露边条）时不可点**。分数区同理。见第八章。

> **实施订正（2026-10-19 用户口径）**：资产区从"每张露 36px"改为**折叠成一摞 +「×N」+ 悬停弹卡列表**
> （`CardLayoutHelper.LayoutPile` + `CardCountBadge` + `CardBadgePeek`）；**分数区保持每张露 36px**。
> 另：资产卡**不**纳入"场上点选"候选 ⇒ 本节"层叠态候选/选中高亮"暂不需要实现（将来纳入时再按二选一补）。

### 决策 5：手牌 hover 上浮

- 复用 `CardUI` 已有 `MouseEntered/Exited`（`CardUI.cs:105-114`，现经 `CardPreviewBus.RequestHover/EndHover` 弹整卡预览浮层）。
- 悬浮时本体上浮（~40px）+ 放大（~1.3x），`ZIndex` 提升至 `Layers.CardDragging` 之下、`CardBase` 之上。
- 与 `_Process` 平滑归位协调：用独立"悬浮偏移"叠加在布局位置之上，不改 `_targetPosition`。
- **【必做 · 与浮层互斥】** 同一信号已被 `CardPreviewBus` 占用 ⇒ 若不加约束，"上浮放大"与"整卡预览浮层"会**同时发生**；  
  且手牌上浮会顶破 `Player1Area` 的高度上限（`Scenes/Arena/Arena.tscn:88-89` 为 `1920×250`，196×1.3 ≈ 255px 再加 40px 上浮已越界）。故：
  - 手牌 hover **只做上浮放大**，**抑制** `CardPreviewBus` 的整卡预览（手牌本就整张可见，无需再弹浮层）；
  - 上浮量与放大倍率须**与 `Player1Area` 高度上限反算**（或允许溢出但 `clip_contents = false` 并抬高 `ZIndex`）。

## 五、性能与可靠性

- **布局复杂度**：层叠/平铺均 O(n)，n 通常 < 20，无瓶颈。
- **浮层复用**：扩展 `CardHoverPreview` 承载多卡平铺，**不新建第二个浮层**（避免层级/总线冲突）。
- **同宿主多触发源必须互斥（新增）**：同一张宿主卡上会同时存在三类触发源 —— `CardPreviewBus` 整卡预览  
  （`CardUI.cs:105-114` 注册）、角标（决策 3）、层叠 hover（决策 4）。**任一时刻只允许一个浮层**，优先级：  
  **角标 / 层叠列表浮层 > 整卡预览**。鼠标从角标/层叠热点移入宿主卡本体时，先关闭列表浮层再决定是否弹整卡预览；  
  手牌按决策 5 直接抑制整卡预览。
- **减少重排**：折叠态不再执行封印/附属偏移布局，反而**降低**开销。
- **双端一致性**：几何常量与算法集中 `CardLayoutHelper`，`Arena`/`ArenaOl` 只调用。

## 八、与「选卡找卡方案」的接口约定 ★

### 8.1 执行顺序

**先执行 `选卡找卡UI优化方案.md`（3 批次），再执行本方案（已确认）。** 理由：

1. 选卡方案修的是**阻塞性缺陷**（高亮却点不动、地区高亮不可见、手牌点击被拖拽吞掉），优先级高于体验提升；
2. 选卡方案建立"**候选卡有可见场上 UI 即可点选**"的契约（`PickCandidateCardUidAt`），本方案的**折叠/层叠**正要动这些卡的可见性 → **必须先建立契约再改造**；
3. 选卡方案 3.1 的 **cat-1/cat-2 分类规则**是本方案决策 3/4 的**前置知识**。

### 8.2 cat-1 / cat-2 分类（选卡方案定义，本方案必须遵守）

| 类别                              | 成员                                                                                                             | 本方案的处理                    |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------- | ------------------------- |
| **cat-1**（提示窗：场上高亮 + 左键即选）      | 争夺区角色/暗藏者｜**结附于地区**的附属（`IsAttached && AttachedTo==null`）｜**封印于地区**的封印（`IsSeal && SealedBy==null`）｜自己手牌｜地区本身｜秘社 | **必须保持场上可见可点**（**一律不折叠**） |
| **cat-2**（选择窗：卡面网格 + 区域标签 + 确认） | **结附/封印于卡**（`AttachedTo!=null` / `SealedBy!=null`）｜**资产（无条件）**｜牌库｜墓地｜对手手牌｜放逐区｜计分区｜堆叠                           | **可折叠/层叠**（走选择窗，不依赖场上点选）  |

### 8.3 【强冲突】封印/附属折叠必须分治 —— 完整口径已并入决策 3

- **冲突**：选卡方案要求"候选有可见 UI 即可点选"；本方案折叠会隐藏 UI ⇒ `PickCandidateCardUidAt` 命中恒为假。
- **分治口径（生效版见决策 3，本节为摘要）**：
  - **结附/封印于地区**（cat-1）→ **不折叠**，继续由 `ArrangeAreaAttachmentsAndSeals()` 在地区容器内平铺，场上可见可点
  - **结附/封印于卡 / 结附于秘社**（cat-2）→ **折叠为角标**（走选择窗，不需要场上点选）
- **兜底**：折叠态若在某次候选下被要求可见，应**临时展开**（与选卡方案 4.5「选择窗 ↔ 场上点击联动」兼容）。
- **hover 展开面板的成员全部属 cat-2**（无例外）：角标展开＝结附 / 封印于卡（含结附于秘社）；层叠展开＝资产 / 计分区；对手手牌展开＝对手手牌。故"hover 面板可点"只须连到选择窗，**不产生任何新的 cat-1 通道**。

### 8.4 资产 / 分数区：层叠 + hover，可点但走选择窗

- 资产属 **无条件 cat-2** ⇒ **取目标一律走 `CardPickWindow`**，不做"原地悬浮直接选中"。
- 层叠后的 **hover 展开面板可点**，出口＝`CardPickWindow.SelectByUid`（等效点选择窗内该卡，**不直接提交**）；未展开时不可点。
- 层叠态（未展开）的候选 / 选中呈现按**决策 4 末条**处理（位移 + 抬层 或 角标指示，**不新增 / 不复用描边接口**，见 8.5）。
- 分数区同理（未来若成为目标，也走选择窗）。
