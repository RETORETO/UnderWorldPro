## 一、要表达的需求（逐条拆解）

| 秘社 | 卡文 | 限制类型 |
|---|---|---|
| 010 貘组 | 只能包含【黄】和【中立】派系的牌，以及其他派系【星】领域的牌 | 白名单 + 例外(领域) |
| 011 S．P．T执行部 | 只能包含【绿】和【中立】派系的牌，以及其他派系**带有［黑刀］能力图标的人类角色牌** | 白名单 + 例外(类别∧子类别∧图标) |
| 012 爱弗罗德家族 | 只能包含【蓝】和【中立】派系的牌，以及其他派系的**吸血鬼或奴仆角色牌** | 白名单 + 例外(子类别 OR) |
| 013 计时者 | 非【红】且非【中立】派系的牌**不能超过 12 张** | 白名单 + 例外**额度** |
| 014 哨兵 | 只能包含【灰】和【中立】派系的牌，以及其他派系**不具有魔法领域图标**的牌 | 白名单 + 例外(无领域) |
| 015 隐士 | 非【白】且非【中立】派系的牌**不能超过 12 张** | 白名单 + 例外**额度** |
| 016 颂亡者 | 只能包含【黑】和【中立】派系的牌，以及其他派系【死】领域的牌 | 白名单 + 例外(领域) |
| 017 梦魇族群 | 只能包含【紫】和【中立】派系的牌，以及其他派系的**灵体角色或梦境牌** | 白名单 + 例外(关键字∧类别 / 子类别) |

**统一语义**：一张牌合法 ⟺
`该牌的全部颜色 ∈ AllowedColors` **或** `命中 ExceptionRules 中任一条`；
再要求"不合法"的牌**总数 ≤ ExceptionMaxCount**。

- 010/011/012/014/016/017：`ExceptionMaxCount = 0`（一个不合法都不许）⇒ 语义＝"只能包含…以及其他派系的…"；
- 013/015：`ExceptionMaxCount = 12` ⇒ 语义＝"非【X】且非【中立】的牌不能超过 12 张"（且没有例外条目）。

> ⚠ 关键口径（请确认）：**"只能包含【黄】和【中立】"按"该牌的全部颜色都必须∈{黄,中立}"判定**
> （即多色牌中只要有一个非白名单颜色就不合法），而不是"只要含有黄就合法"。
> 依据：卡文把"派系的牌"与"中立"并列，且 011/012 的例外是"其他派系的（具体卡）"——
> 例外只可能落在"颜色不在白名单里"的牌上，否则例外条目就永远用不上。

## 一·补（实测发现：两处数据缺口，必须先定口径）

开工前实测了全库 698 张 `PlayerCards/*.tres` 与 `Card.xml`，发现**"能力图标"这个字段在数据层根本不存在**，
以及一个更大的覆盖问题：

| 实测项 | 结果 |
|---|---|
| `PlayerCardData` / `.tres` 里有"能力图标清单"字段吗 | **没有**。`BaseCardData` 只有 UID/CardName/Score；`PlayerCardData` 只有 6 个**数值**（调查/战力/势力 + 三个先手值），没有"这张牌印了哪些图标（黑刀/白星/…）" |
| 图标信息在哪 | 只在 `Card.xml` 的 `<pt>` 文本里，形如 `［黑眼］［黑眼］［黑刀］［黑刀］［黑星］/2`（`/` 后是防御力）——卡片导出时**只把数字导进了 .tres，图标标签丢了** |
| `.tres` 的 6 个数值与 `<pt>` 图标数吻合吗 | 在**两边都有**的 216 张里**完全吻合**（0 处冲突）⇒ "数字 ← 图标数"这个转换本身没写错 |
| **`Card.xml` 覆盖不全**：698 张 .tres 里 | **216** 张在 `Card.xml` 里有 `<pt>`（图标可还原）；**147** 张在 `Card.xml` 里有卡但**无 `<pt>`**；**335** 张（BH/BQ/CQ/DQ… 系列）**在 `Card.xml` 里根本没有条目** |
| 缺口大小 | 有非零能力数值的 **371** 张里，**199** 张能从 `Card.xml` 还原图标，**172** 张不能 |

**这直接影响 MSJC011**：它的例外是"其他派系**带有［黑刀］能力图标**的人类角色牌"。
- 按 `<pt>` 还原：全库 **88 张**有［黑刀］；
- 若不看图标、只看"战力值>0"：会命中 **173 张**——**会误放过"只有白刀/黑星、没有黑刀"的人类角色**（不是同一回事）。

**建议的最小修法**（不改 698 个文件）：导出期生成一张**图标查表**
`Script/Data/Cards/CardAbilityIcons.cs`（或同目录 JSON），由 `Card.xml` 的 `<pt>` 解析而来，
入表 **199 张**（能把话说到"确证有/无黑刀"）；**查表未命中 → fail-closed 判"无该图标"并打日志**
（宁可收紧不可误放）。相对地，若要 100% 精确，需要你补一份**含全部 698 张 `<pt>` 的 XML**，
我再把图标清单一次性回填进 `.tres`（那会动 698 个文件，建议单独一个批次做）。

> 请选择：**(a)** 先用"查表 + 未命中 fail-closed"落地（推荐，本批可完成）；
> **(b)** 你先提供全量 XML，我这一批就把 `.tres` 回填齐；
> **(c)** 011 的例外先降级为"战力值 > 0 的人类角色"（会误放，我不推荐）。

## 二、`CouncilRestriction` 新增字段

现有字段全部保留、语义不变（`FilterByColor` + `Comparison` + `RequiredCount` 那条老路径继续可用，
001~008 的 .tres 完全不动）。

| 新字段 | 类型 | 默认 | 语义 |
|---|---|---|---|
| `UseWhitelist` | `bool` | `false` | 启用"只能包含"模式。`false` ⇒ 完全按旧逻辑走（向后兼容） |
| `AllowedColors` | `Array<CardColor>` | 空 | 允许的派系颜色白名单；**"中立"＝`CardColor.Brown`**（枚举第 0 值，卡文"中立"在库里就是棕） |
| `AllowColorlessCards` | `bool` | `false` | 无任何颜色标记的牌（`Colors` 为空）是否视为白名单内。**默认 false＝不合法**（fail-closed，需显式放行） |
| `ExceptionMaxCount` | `int` | `0` | **不在白名单内且未命中例外**的牌**允许的张数上限**。`0`＝一个都不许（010/011/012/014/016/017）；`12`＝013/015 |
| `ExceptionRules` | `Array<ExceptionRule>` | 空 | 例外清单，**OR 语义**（命中任一条即豁免）。见下 |

### `ExceptionRule`（新类，`Script/Data/Cards/CouncilExceptionRule.cs`）

复用现有正向字段的**同一套类型**，避免造第二套词汇；并把 `CouncilRestriction` 里已有的
`FilterByXxx` 判定**抽成单一实现**由两边共用（禁止复制粘贴两份匹配逻辑）。

| 字段 | 类型 | 语义 |
|---|---|---|
| `FilterByCategory` / `TargetCategoryFlag` | `bool` / `CardCategory` | 卡类别（如 `角色`） |
| `FilterBySubCategories` | `Array<string>` | 子类别**任一命中**（OR）。**新增复数版**以表达 012「吸血鬼**或**奴仆」、017「梦境」 |
| `FilterByDomain` / `TargetDomain` | `bool` / `MagicDomain` | 魔法领域（010【星】= `Star`、016【死】= `Death`） |
| `RequireNoDomain` | `bool` | "**不具有**魔法领域图标"（014）。true ⇒ `card.MagicDomains` 为空才命中 |
| `FilterByKeyword` / `TargetKeyword` | `bool` / `string` | 关键字（017「灵体」；判定复用 `HasKeyword ∪ HasInherentKeyword`，与 `DeckSearchFilter` 同源） |
| `FilterByIcon` / `TargetIcon` | `bool` / `string` | 能力图标（011「**［黑刀］能力图标**」；判定 `card.HasIcon(...)`） |

**为什么 011 用 `FilterByIcon` 而不是关键字**：卡文写的是"带有［黑刀］**能力图标**"，
卡库中［黑刀］是**图标**（`PlayerCardData` 的图标/属性通道），不是 `Keywords` 词条。
用图标通道才能与引擎其他地方（`HasIcon` / `IconToAttribute`）同解。

一条 011 例外 = `类别:角色` ∧ `子类别:人类` ∧ `图标:黑刀`（三个字段 AND）；012 例外 = `类别:角色` ∧ `子类别:{吸血鬼,奴仆}`。

## 三、方法行为（唯一实现，三点收口）

```
IsSatisfiedBy(deck) → UseWhitelist ? 违规张数 <= ExceptionMaxCount : 旧逻辑
GetActualCount(deck) → UseWhitelist ? **违规张数** : 旧逻辑（满足筛选条件的张数）
Describe(actual)     → UseWhitelist ? 新文案 : 旧文案
```

判定单卡是否"在白名单内"：

```
inWhitelist(card)
  = (card.Colors.Count == 0 ? AllowColorlessCards
                            : card.Colors.All(c => AllowedColors.Contains(c)))
    || ExceptionRules.Any(r => r.Matches(card))
```

`GetActualCount` 在 whitelist 模式下返回**违规张数**——这样 013/015 在构筑界面
显示"当前 7 张 / 上限 12 张"、010 显示"当前 2 张 / 上限 0 张"，语义天然对齐 `IsSatisfiedBy`。

### `Describe` 文案（供"卡组违规"提示与构筑界面）

| 场景 | 文案 |
|---|---|
| 010 | `只能包含 黄色/中立 派系的牌，以及其他派系：领域为 星空 的牌（当前 2 张，上限 0 张）` |
| 011 | `只能包含 绿色/中立 派系的牌，以及其他派系：类别为 角色 且子类别为 人类 且图标为 黑刀 的牌（当前 0 张，上限 0 张）` |
| 013 | `非 红色 且非 中立 派系的牌不能超过 12 张（当前 7 张）` |
| 014 | `只能包含 灰色/中立 派系的牌，以及其他派系：不具有魔法领域图标的牌（当前 0 张，上限 0 张）` |

（`ExceptionMaxCount == 0` 时用"只能包含…"句式；`> 0` 时用"非…不能超过 N 张"句式。）

## 七、口径确认结果（**用户 2026-09 已拍板，本稿已按此落地**）

1. **"只能包含"的判定口径**：**只要含白名单颜色就合法**（不要求全部颜色都在白名单里）。
   > 实测参考：现有 698 张 `PlayerCards/*.tres` **全部是单色**（`Colors` 每张恰好 1 项），故两种口径在现有数据下等价；
   > 本实现按用户口径（"任一命中"）写，`IsAllowedInWhitelist` 对多色牌取"含即合法"。
2. **"中立"的枚举值**：确认 **`CardColor.Brown`**（`PlayerCardData.Colors` 注释原文即"默认棕色（中立）"，全库 154 张棕牌）。
   `Describe` 在白名单语境把棕色显示为"中立"，其它场景仍显示"棕色"（`WhitelistColorName` vs `ColorName`）。
3. **013/015 的 `GetActualCount` 语义**：白名单模式下返回**违规张数**（UI 直接显示"当前 7/12"）。
4. **011 的能力图标**：**能力图标即为"调查/战力/势力 ＋ 三个先手值"的统称**，调查/战力/势力能力都来源于能力图标
   ⇒ **按"战力 > 0"判断，明确不含先手战力**。因此**不引入** `Card.xml` 的 `<pt>` 解析或任何图标查表
   （数据层只有 6 个数值、没有图标标签；且 `Card.xml` 只在 216/698 张里有 `<pt>`）。
   实现：构筑侧 `CouncilExceptionRule.FilterByAbilityIcon/TargetAbilityIcon="黑刀"` ← `PlayerCardData.Strength > 0`；
   效果侧 `TargetRestriction.HasAbilityIcon`（`Param="黑刀"`）← 印刷战力 或 `CurrentStrength`（含授予）。
5. **014 的"不具有魔法领域图标"**：按 `MagicDomains` 为空 **或只含哨兵值负数** 判定
   （实测无领域卡在 `.tres` 里就是 `Array[int]([-1])`）。实现：`CouncilExceptionRule.RequireNoDomain`。
